# 粗剪启动规则（roughcut-launch）

用户说"粗剪"（"粗剪一下/粗剪这几个视频/使用粗剪"）时，自动按本规则执行，无需再问。

## 1. 任务登记

- 素材：`E:\PR导出\*.mp4`（只读，绝不写入/覆盖）。
- 任务目录：`C:\Project\永劫无间\123\<下一个编号>.<素材文件名>`（编号只增不重置；复用已有目录时沿用）。
- 模式：`complete_combat_roughcut`（详见 `references/complete-combat-roughcut.md` 三层结构）。

## 2. 并行编排：角色分工 + 切分 + 流水线返回 + 证据合并 + 阻塞处理

战斗"算不算、从哪到哪"仍按 `complete-combat-roughcut.md` 三层结构判，本节只管"谁干、切多细、回来怎么接"。时间线字段名以 `scripts/validate_combat_timeline.py` 为准（`engage_start`、`deleted_intervals`）。

### 2.1 角色分工（一路一角，不兼任）

共 8 种角色，数量不限（同一种角色可同时存在多路，如扫描员 seg1–seg6）。每路只认一种角色，不一人分饰两角。

| 角色 | 职责一句话 | 输出文件 | 禁止事项 |
|---|---|---|---|
| 指挥（主对话） | 只派工验收落台账派下一步，不看图不动手不对单 | `reports/dispatch_ledger.md` 更新、下一路派工 prompt、`reports/merge_decision_v*.md` | 禁止 `Read` 任何图片/缩略图/联系表；禁止跑 FFmpeg/whisper/scenedetect/auto-editor；禁止直接改时间线 JSON；禁止口头验收（必须落台账才算数） |
| 扫描员 | 对分派区间密集看帧，只回答"有没有战斗、边界在哪、证据在哪" | `reports/segN_scan_report.md`（必填字段见下）+ 证据帧清单（秒级命名）+ `shots/segN/contact_*.jpg` | 禁止跨段看帧/下结论；禁止输出预览 MP4；禁止改 `timeline/`；禁止一次提交超预算看图 |
| 修线员（合成时间线） | 把多路扫描报告合成一条无缝时间线，不重扫 | `timeline/combat_episodes_v<N+1>.json`（`deleted_intervals` 内嵌）+ `reports/merge_decision_v<N+1>.md` + `reports/v<N+1>_validate.json`（脚本实跑） | 禁止重抽帧重看图定边界；只认书面报告加证据帧路径；禁止把 `needs_review=True` 送预览；禁止手动对账代替脚本 validate |
| 字幕员 | 管字幕映射与断裂检查，不管选片 | `captions/program_v*.srt` + `reports/subtitle_map_v*.md`（跨段断裂零横跨） | 禁止改战斗边界；禁止源字幕横跨 episode 边界；禁烧录禁内嵌字幕流（只出外挂 SRT）；禁止把 faster-whisper 当说话人身份 |
| 渲染员（预览） | 只按冻结时间线渲染低清预览，不管对错 | `preview/review_v*.mp4`（粗剪只到 720p）+ `reports/preview_decode_v*.log` | 禁止改时间线；禁止出 4K master；禁止在错预览上叠剪；禁止复用区间已变的旧分段（复用必须 ffprobe 对时长） |
| 自审员 | 按 §3 四遍视角独立挑刺，不改线 | `reports/<版本>_round<轮>_audit.md`（命名细节按 §3.5 三分立执行） | 禁止改 `timeline/` 与重渲；禁止复用同一批图做同一结论；禁止问题口头带过不落盘 |
| 复验员 | 只验"上轮问题是否修好"，不扩范围 | `reports/reverify_v*_*.md`（逐条闭环） | 禁止开新问题分支；禁止用旧预览当 QA 依据；禁止跳过 validate 实跑 |
| **删除段审计员**（864 新增，见下） | 逐条 `deleted_intervals`，用**与画面判定无关的独立信号**交叉验证"这段真的没有战斗" | `reports/deleted_audit_v*.md`（逐条：区间／独立信号命中与否／结论） | 禁止用删除段自己的 `reason` 当证据；禁止改 `timeline/`；禁止把"reason 写得详尽"当作核验通过 |

#### 删除段审计员（864 §4.1，必须每轮派工，2026-10-01）

**为什么新增这个角色**：864 派出 **7 路对抗审 + 4 遍自审 + 3 路验收**，全部任务书都指向「报告你这一区间的问题」「只报 v{N} 自身的问题」「逐条核销上一版」「核验本版冻结件」。

**没有一份任务书要求过"检查被删掉的区间里是否有被冤杀的战斗"。** 结果：源 896–908 有一场完整战斗（语音 897.97「开始了」/ 901.80「弹太快了」/ 904.80「没事我杀了」），整段躺在删除段 `[810, 910.99)` 里被删光。用户看出来的原话是「6分28 那一场战斗进来，我都是直接开大的状态。那肯定是之前有战斗啊」。

删除段的 `reason` 写得非常详尽（交易、导航、搜刮、补给，每条都有 18 条取证路径），**看起来完全合理——但没有任何人用独立的战斗信号去交叉验证它**。详尽的理由本身就是最大的陷阱。

**职责与判据**：

1. 取时间线 `deleted_intervals` 全部条目，一条不漏。
2. 对每条用**与画面判定无关的独立信号**扫描：语音战斗词（杀了/开大/他要走死/拉药/弹太快了/我来了…）、音频活动强度、队友播报、击杀播报。
3. **任一命中 → 强制人工复核**，并回看该间隙前后是否属于同一场战斗（很可能是）。
4. 零图片成本优先：先跑语音战斗词扫描，这是 864 唯一逮到漏战的手段。

**「开大」诊断启发式（零成本，优先做）**：若某个 episode 入片首帧**已经处于技能释放／开大进行中**，说明前置战斗很可能被删了 → **立即回查该场 `source_start` 之前**。

**「用户说抽查」的含义（T5）**：用户说「我只看了一些，找到这有问题，**类似的问题肯定还有的，都去修正一下**」时，这是**要求系统性排查**，不是许可只修他点名的那一处。864 第 5 版只修了点名的 1 处，第 6 版才发现同类共 4 处。


主Agent不看图做审片（省预算），只验 JSON/validate/解码/文字审计；定点裁决由主Agent下发。

扫描员报告必填字段（缺一字段指挥判"未回"，打回重做，不计入合并输入）：区间 `[seg_start, seg_end)`（源秒）；结论三选一（有战斗 / 无战斗 / needs_review）；episodes（暂定 source_start/source_end/engage_start/impact_points/outcome_time/event_types/confidence）；deleted_inside（段内删除子区间 start/end/category/证据）；边界证据（每个边界 ≥2 独立信号 + 证据帧绝对路径 + 联系表路径）；预算记录（已看图数/剩余预算/分轮结论路径）；末尾 `STATUS: DONE / BLOCKED`（BLOCKED 写断点秒点与已落盘证据）。

### 2.2 任务切分与自适应并行（常规默认，最快仅明示）

- 自适应档位速查（指挥在 T0 台账写明档位 + 在途上限 + 波次；默认常规，用户明示"最快"才切最快）：
  - 常规档：80–90 秒/路 + 5 秒重叠，总路数 `ceil(时长/85)`；单任务在途扫描上限 10。
  - 最快档（e4）：60 秒/路下限（禁 <60 秒，语义最小单位）+ 5 秒重叠，总路数 `ceil(时长/60)`；单任务在途扫描上限 16–20。
  - 全局在途上限 24（跨任务扫描 + 对抗审合计；验收/渲染/修线串行：NVENC 锁 + 单写者）。超限排队，完一路补一路。禁 3 任务 × 20 = 60 全发。
  - 定档输入：时长 + `event_candidates` 密度 + hotM/hotF 簇 + 转写是否 BLOCKED（BLOCKED 走常规，视觉代偿更吃帧，不切最快）。
- 同视频按大删除段切，一路 80–90 秒：先单路快筛做出"战斗候选 vs 大删除段"初版划分（不进密集看图），每个待密集核验的大删除段按 80–90 秒切一路（如 270 秒缺口切 3–4 路）。已明确的战斗 episode 本体不切碎，一个 episode 归一路端到端负责（含前后 `lead_in + recovery_tail` 扩展检查）。段间必须有 5 秒重叠带（`segN_end = segN+1_start + 5s`，拼接互证区）。命名 `seg1 [0,90)`、`seg2 [85,175)`……起止写源秒，保留 1 位小数。
- 多视频默认一素材一路并行，每路内部再按上一条拆段；跨素材不拼线、不共用预算、不共用证据，各素材独立台账行组与版本号；仅终局需跨素材选集锦时由修线员做一次跨素材 `merge_decision`，输入仍是各素材冻结报告，不重扫。
- 自动拆段增派（触发任一即拆，不等人不请示）：素材 >30 分钟登记时直接拆段；单路区间 >120 秒一轮看不完则一分为二（前后各 80–90 秒，重叠 5 秒，原路结论保留为初筛输入）；单路 `STATUS: BLOCKED` 或超时未回按 §2.5 冻结重派。增派无上限，"数量不限"按此执行。
- e4极限并行档（来源 `123\workflow_upgrade\e4_parallel_throughput.md`，升级不覆盖常规档）：素材 ≥10 分钟且用户要最快时切分下限允许到60秒/路（常规仍80–90秒/路，禁止<60秒/路；60秒已是独立下结论最小语义单位）。极限切分算法：步长60秒、重叠5秒，`segN = [(N-1)*60, (N-1)*60+65)`，末路收至片尾；战斗本体跨线时episode归一路端到端、相邻路让位（让位≤15秒，超出则该episode独立成一路）。单素材并发上限 `ceil(时长秒/60)+4`（+4为阻塞换路预留额度，编号 `segNb`，不先派只占编号）。后台一次全发（不分波试水），回来一路动一次（首回出partial草稿、相邻回做预合、半数回出全量草稿、全回出冻结候选，字幕/渲染/自审只认冻结版）。台账 `reports/dispatch_ledger.md` 为唯一真源（格式与状态封闭词表见e4设计稿，口头回来不算回，落盘加台账才算回）。超时换路按 §2.5 执行并加编号规则：冻结原路（标阻塞冻结）→ 派 `segNb` 写明 `resume_from=<断点源秒>` + 复用证据路径（复用不复看，预算从0起）→ 新旧择优合入主线，另一路归档不双合。

### 2.3 流水线返回（谁先回先动，不等最慢）

- 全部扫描路以后台并行发出（一次下发多路 prompt）。派工 prompt 必须含绝对路径（源文件、任务目录、联系表目录、报告落盘路径、台账路径），禁止相对路径；全部输出路径必须以任务目录 `123\<编号>.<素材文件名>` 为前缀，禁写项目根、skills、scripts、docs、源盘、乱码/星号/变量展开路径。每Agent prompt 必须包含：必读文件（AGENTS.md → README.md → docs/WORKFLOW.md → SKILL.md → complete-combat-roughcut.md → 一个已收敛范例任务）、工具固定路径（`.video-tools\venv` Python + FFmpeg 实际目标，禁新建环境/禁安装）、工作路径禁令（本段全文引用 §2.7 首条）、看图预算规则（单轮新增≤10/累计50，先跑 `scripts\check_image_budget.ps1`）、审计落盘命名（按 §3.5 三分立）、只记 `reports/workflow_notes_*.md` 不改共享文件、不出4K（粗剪到720p预览为止）。指挥下发后立即写台账"已派/未回"，不做任何看图与渲染。
- 任何一路 `STATUS: DONE` 落盘，指挥立即验报告必填字段 → 台账标"已回/已验收"（岛草稿记 `PARTIAL`、搭桥记 `BRIDGED`，只追加不改旧行）→ 派下一步，不等其他路。触发器：回 1 路即出 partial 草稿（`merge_decision_vN-partial-r{k}`）；回 2 路且相邻即预合岛；回半数即全量草稿；缺路成岛（如 1–3 岛 A、5–7 岛 B，缺席记 `SEAM` 缝）；缺席路回 + 双侧互证通过即搭桥升段；全回 + 双证齐 + validate pass 即冻结候选。字幕员、渲染员、自审员只认冻结版，不认 partial。
- 台账 `reports/dispatch_ledger.md` 是唯一真源：每路一行（路/区间素材/状态/报告路径/下一步），回来一路更新一次，口头"回来了"不算回，落盘加台账才算回；每次更新追加一行时间戳附注，不覆盖历史；修线/渲染/自审/复验同样进台账（待触发/已派/已回/已冻结）。T0 行必须写明档位（常规/最快）+ 在途上限 + 波次；每路行必须写派工时间/回收时间（计时基线：848 扫描波 28 路约 1 小时级、修线接管 4 轮教训见 §2.5）。

### 2.4 证据合并（只认书面报告加证据帧路径，不重扫）

- 修线员唯一输入是 §2.1 报告 + 证据帧绝对路径 + 联系表路径。证据帧必须秒级时间戳命名 + provenance 可查，来源不明的旧残留帧不得作证据（沿用 `complete-combat-roughcut.md §3.2`）。分辨率分级沿用初筛 320px → 判定 640px → 定点 960px，报告写清结论用的是哪一级，稀疏图初筛结论不得直接定生死。
- 相邻两路重叠带（5 秒）必须双方各给至少 1 个独立证据（画面三信号/音频连续战斗声/转写连续战斗语音中至少各一，互不复用同一帧）互证才合并；互证失败（一方说战斗一方说跑图、边界差 >3 秒、一方 `needs_review`）不硬合，按拆段保留处理（各按保守边界落盘，中间缝标 `needs_review`，派一路只查重叠带前后 10 秒高清逐秒定点复核）。
- 任一边界改动必须同步更新相邻 `deleted_intervals` 并重跑 `validate_combat_timeline.py` 无缝覆盖检查。`merge_decision_v*.md` 必须写用了哪几路报告、每段采信谁的边界、重叠带互证结果、删除段分类、validate 实跑结论，不写即视为未合，不送渲染。任一边界改动即新版本号，旧预览立即作废归档，不得作 QA 依据。

### 2.5 阻塞超时处理（冻结旧路，换新路从断点重做）

- 超时定义（任一即判）：派工后无落盘超过约定轮次，或报告 `STATUS: BLOCKED`，或缺必填字段两次打回仍未补齐。约定轮次默认 3 轮（T0 台账写明）；超时即冻结换 `segNb`，禁如 848 `repair-v1` 等 4 轮（教训：28 路扫描全回后合并 blocked 4 轮才转接管，瓶颈在串行合并不在扫描）。
- 处理三步：冻结原路（台账标"阻塞冻结"，保留已落盘证据，不删除）；派新路从断点秒点重做（新 prompt 写明 `resume_from = <断点源秒>` + 已有证据路径，新路复用证据，不复看已看图）；新旧回来后以证据更全、边界双信号更硬者为准，另一路归档为初筛参考，不合入主线。
- 禁止原地死等、催原路"再看看"、把阻塞路半成品直接合入主线。

### 2.7 工作路径铁律（防根目录零散产物，违反即打回）

- 唯一工作目录：`123\<编号>.<素材文件名>`。全部派生文件（抽帧、联系表、报告、字幕、预览、时间线、缓存、日志）只许落此，禁写项目根、skills、scripts、docs、assets、源盘（`E:\OBS`/`E:\PR导出`只读）、`%TEMP%`/系统临时目录、乱码/星号/变量展开路径（如 `$T`、星号目录、编码错乱目录）。误放文件的隔离位置是任务内 `cache/quarantine/`，禁止隔离到任务目录外（纠正 848 旧例：落错层副本曾隔离到 `%TEMP%`，属二次违规）。
- 输出路径必须以任务目录绝对路径为前缀；FFmpeg `-y` 输出、抽帧 pattern、联系表输出、报告落盘任一不在任务目录内，指挥判"未回"打回重做，不计入合并输入。
- 子 Agent 启动先 `dir` 确认任务目录存在再开工；发现根目录 `f_*.jpg`/`thumb_*.jpg`/散 `*.mp4` 即停手上报，不得复用、不得覆盖、不得二次写入。
- 单写者矩阵：扫描员只写 `shots/segN/` + 本路 `reports/segN_scan_report.md`；修线员只写 `timeline/` + `reports/merge_decision_v*.md`；渲染员只写 `preview/`；字幕员只写 `captions/`；自审/复验/验收只写本路 `reports/` 文件；台账只由指挥追加。跨路写即违规，判"未回"打回。
- 派工 prompt 强制字段（缺段指挥拒发）：任务目录绝对路径前缀断言 + 预检 `dir` + 禁写清单（本条第一款全文）+ 看图预算规则 + 落盘命名（§3.5 三分立）+ 只记 `reports/workflow_notes_*.md` 不改共享文件 + **必答项「你负责的区间之前紧邻的那条删除段，是否合理？」**（864 §4.1：7 路对抗审 + 4 遍自审 + 3 路验收全部只查保留区间，没有任何一份任务书要求查被删区间，漏掉的那场战斗就躺在里面）+ **每轮必派删除段审计员一路**。落盘后指挥做路径前缀复核（`Get-ChildItem` 任务根散文件计数），违规按第二款处理。

### 2.8 零星合并/岛式合并（g升级，来源 `123\workflow_upgrade\g-shard-merge.md`）

- 岛定义：连续已回路的闭合集合（如 1–3 岛 A、5–7 岛 B），内部 5 秒重叠须双方独立证据互证；缺席路两侧断面记 pending 缝（`SEAM-<缺席路>L/R`），只出 partial 草稿，永不冻结。partial 命名 `merge_decision_vN-partial-r{k}`（N 为父冻结号，永不转正，只能被修线员重算替代；字幕/渲染/自审禁认 partial）。
- 搭桥：仅当缺席路回来且与两侧各完成互证，一次性闭合双缝；任一失败则不合拢、不升级冻结版。搭桥必重跑 validate + 双证，不齐则保持分岛。
- 重叠带单裁决：同一 5 秒带全局单裁决，裁决权独归修线员；岛端只交证据包、无自判合并权；失败缝挂主张岛名下并版本 +1 冻结为断开，证据留痕可复用但必须重判。
- 台账三态（只追加，不改旧行）：岛草稿 `PARTIAL`、搭桥 `BRIDGED`、冻结 `FROZEN`（全局唯一；须引用全岛 PARTIAL seq + 双证据号且 base_ver 一致；FROZEN 计数 >1 即锁账停渲染）。缺路相邻禁预合：缺路两侧不断言跨越结论，只记缝；重叠带无双方互证一票否决；非冻结直拒渲染并回滚。
- 版本血统（一动全废）：任一边界改动，冻结候选 +1，旧 N 下全部 partial 作废，各岛基于新 N 重做互证后重出。
- 编制：1 修线员（唯一写者）+ 2 预合专员（并行打岛草稿，只出 `merge_decision_v*-draft`，禁碰时间线与台账）+ 学徒池备料。合并持全局写锁单跑（合并在途 1、离线岛 ≤2），其余只做只读岛草稿。
- 必须串行的环节：validate 实跑仅修线员单进程；冻结判定全回后一次判定；对抗审举证可并行、定稿单人一次；成片 NVENC 全局锁只认冻结版（预览可并行，成片禁并行）。触发器见 §2.3（回 1 路 partial、相邻预合、半数全量草稿、缺路成岛、搭桥升段、全回冻结候选）。

### 2.6 单写者与配比（多 Agent 契约，术语与 e4/d1 一致）

- 单写者：台账只由指挥追加，时间线与合并决策只由修线员写；预合专员只出 `merge_decision_v*-draft` 岛草稿，禁碰 `timeline/` 与台账；扫描/字幕/渲染/自审/复验只写本路产物，禁跨路写。修线只认书面报告加证据帧路径，不重扫；草稿带 `-partial` 后缀，不冻结、不送字幕渲染自审；任一边界改动即加版，旧预览作废。
- 配比：单素材稳态为一修线主线加二至三路在途核验（扫描/对抗审/验收的滚动组合，不囤积、不预派分叉）。多素材一素材一组，独立台账行组、独立预算、独立版本号，不共证据、不拼线；仅终局跨素材选集锦时做一次跨素材合并决策。
- Token 纪律：跨路只传摘要加绝对路径，不贴全文、不贴帧。超 10 帧先拼联系表（一表计一图），边界前后才补小批量高清。看图前先数图并跑 `scripts\check_image_budget.ps1`，单轮新增不超 10 张、累计不超 50 张；打满开新路复用结论不复看。

## 3. 自审与验收：4遍自审 + 执行验收分离 + 四验收角色 + 推版规则 + 三分立命名

### 3.1 自审标准：4遍不同方式，零问题才停

- 第1遍切点视角：节目切点±2s高清帧，上一场收束后衔接。
- 第2遍连续性视角：段中抽帧（与第1遍错开），无拉扯挖空、无跑图混入。
- 第3遍随机复核视角：随机位置 + 删除段转写交叉 + 终局链。
- 第4遍状态因果链视角：列出全部玩家状态突变（神兽之力/变灵魂/阵亡/复活/进出回阳境），逐一要求来源战斗在片中。
- 有问题就修时间线（版本号+1）+重渲预览+计数重计；连续4遍无问题冻结。

自审员可与执行同队，但不得与修线同人；视角必须错开，不得复用同一批图做同一结论。自审没交，该版不算完，不派验收。

### 3.2 执行与验收分离（做线的人不验自己的线）

- 同一版本号 vN 的修线员、字幕员、渲染员不得兼任该版本任何验收角色，验收派工时指挥必须换新子 Agent（新会话窗口）。验收员禁止改 `timeline/`、禁止重渲预览、禁止补抽帧定新边界，发现边界问题只写"问题 + 源秒点 + 证据"，修线回到修线员做（新版本号）。指挥本人不看图、不复算、不下口头通过，只检查验收报告是否落盘、字段是否齐全、问题清单是否闭环。
- 每版冻结（时间线 JSON + validate 实跑 JSON + 现行预览 MP4 + 解码日志 + 自审报告齐）后派独立验收 Agent，prompt 写明"未参与本版执行，只认落盘文件独立复算"，输入只给绝对路径。独立复算五式（项目 Python / ffprobe 只读重算，不采信手算）：validate pass（重读 `vN_validate.json`，确认 `pass=true`，数 episode/deleted 条数，warnings 逐条分类，预期内 `needs_review` 标记须点名）；分段求和（各段 `source_end − source_start` 求和对 header 总节目秒，0.01 秒级核对并写出两数）；ffprobe 时长（预览容器时长对节目总秒，约 ±0.3 秒内记舍入，超差列问题）；字幕条数（数 SRT 条数，对 stats，跨段断裂零横跨）；报障闭环换算（节目秒 P 换算源秒 `S = episode.source_start + (P − episode.program_start)`，判定落点在连续战斗区间而非旧切点后 1 秒，写出算式与区间）。
- 验收全程只读（`dir` / `Read` 文本 JSON / 项目 Python 只读算术 / `ffprobe` / `stat`），不跑 whisper/scenedetect/auto-editor，不渲染不安装；每条结论写来源文件绝对路径 + 关键数字。

### 3.3 四验收角色（互相独立，可并行，可 0 图）

| 角色 | 验什么 | 输入（只读） | 输出 | 判定要点 |
|---|---|---|---|---|
| A. 报障闭环验收员 | 用户报的每个中断/漏战点是否真修好 | 上轮报障清单 + 新版 `combat_episodes_vN.json` + `program_map_vN.json` | 报障闭环表（换算式 + 落点区间 + 成立/不成立） | 纯数字换算；落点在连续战斗区间判成立，仍在切点 ±1 秒或删除缝判不成立 |
| B. 时间线数字验收员 | validate、分段和、单调无重叠、无缝覆盖 | `combat_episodes_vN.json` + `vN_validate.json` + `program_map_vN.json` | 数字复核表 | `pass` 须 true；唯一允许非空 warnings 是已声明的 `needs_review`（须点名）；分段和须对上 header；episode 单调无重叠；`deleted_intervals` 内嵌本体（独立审计文件不算过门） |
| C. 预览字幕验收员 | 预览可看、字幕可对、零字幕流 | `preview/review_vN.mp4` + 解码日志 + `captions/preview_vN.srt`（+ stats）+ ffprobe | 存在性 + 解码 + 时长对照 + 字幕条数 + 断裂结论 + ffprobe 字幕流为 0 | 解码全片通过；时长差舍入级；SRT 写出条数；stats 缺失须声明口径落处，不得跳过；MP4 内含字幕流或烧录像素字即 FAIL |
| D. 合规验收员 | 源片未动、无 4K 偷跑、目录合规 | 源片 size/mtime + `deliverables\` + 目录文件名扫 | 合规表 | 源 size/mtime 无本次写入迹象；`deliverables\` 为空（粗剪阶段）；无 `*master*/*4k*/*3840*/*final*`；仅 720p 预览；命名后缀差异须声明映射，不记缺失 |

派工 prompt 通用必备行：独立验收、未参与执行、只读核验；必读 AGENTS.md → README.md → docs/WORKFLOW.md → SKILL.md → complete-combat-roughcut.md → deliverables-and-qa.md；输入与输出写绝对路径（输出落 `reports/accept_<任务>_vN.md` 对应章节，末尾 `STATUS: PASS/FAIL` + 问题清单含源秒点）；只用 dir/Read/项目 Python/ffprobe/stat，禁新建环境禁安装禁出 4K，本路 0 图可完工。

### 3.4 问题汇总与推版（先汇总，后推版，不边验边改线）

- 四路验收报告全部落盘前，修线员不得开 vN+1。指挥收齐后把四路问题合并成唯一问题清单（去重、标源秒点、标所属 episode/删除缝），清单是推下一版的唯一输入：为空则进冻结候选（等复验闭环），非空则按小修/大修分流。新发现超范围问题另起 audit，不混入本次闭环。
- 小修：单边界 ±2 秒内微调，不增删 episode，不动相邻删除段分类；修线只改该边界 + 同步相邻 `deleted_intervals` + 重跑 validate + 重渲预览，仍须版本号 +1。大修：新增段/删段/合并拆分/终局结算延长改 `source_end`/状态因果链补漏战；同小修全套，另加 `merge_decision_vN+1.md` 写明采信与互证、删除段分类重审、相关验收全重跑。分流由指挥定，拿不准按大修处理。
- 版本铁律：任一边界改动即新版本号；旧预览立即过时归档，不得作 QA 依据，QA 从新预览起计；`deliverables/` 旧 delivery 过期未更新不算冻结失败，但终版须统一；分段复用仅当 episode 区间未变且 ffprobe 对时长通过。复验员只验"上轮问题是否真修好"（逐条问题→修复→证据，通过/打回指源秒点，不扩范围）；复验不通过不冻结。自审回答"这版还有没有问题"，复验回答"上轮问题是不是真没了"，两者缺一不可，顺序不能反。

### 3.5 验收报告命名三分立（不混写）

全部落在任务目录 `reports\` 下：

| 文件 | 谁写 | 何时写 | 写什么 | 不写什么 |
|---|---|---|---|---|
| `reports/selfaudit_<任务>_vN.md` | 自审员 | 冻结前，每版一次 | 四遍视角、抽帧区间、结论、问题清单（修线指令） | 不写最终 PASS/FAIL 冻结结论，不写复验闭环 |
| `reports/accept_<任务>_vN.md` | 四验收员（各写章节）+ 指挥汇总 | 冻结后，每版一次 | 存在性、validate 复算、分段求和、ffprobe 对照、字幕条数、报障闭环表、合规表、不通过项/待用户决策项 | 不混入自审过程帧记录，不代替 reverify 逐条闭环 |
| `reports/reverify_<任务>_vN.md` | 复验员 | 新版出来后，对上轮问题 | 逐条"问题 → 修复 → 证据"闭环（通过/打回 + 源秒点） | 不开新问题分支（新发现另起 audit） |

`<任务>` 取素材编号（如 `840`），`<vN>` 取时间线版本号（如 `v3`），多任务各独立三件。命名后缀差异（如 `_842` 映射件）在 accept 中声明映射，不另起体系。旧过程审计（`vN_roundK_audit.md`、`roughcut_*_review_ready.md`）结论被三分立文件吸收后按 `deliverables-and-qa.md` 生命周期清理。

### 3.6 预览对抗审（e3升级，来源 `123\workflow_upgrade\e3_preview_adversarial.md`）

- 每版冻结后必派与本版执行无关的对抗审 Agent（新会话窗口，修线/字幕/渲染/自审不得兼任），按节目时间把冻结预览切成60–90秒/路多路并行逐段看内容（段数 `ceil(节目总秒/75)` 摊平，段间节目轴5秒重叠带 `segK_end = segK+1_start + 5s`，命名 `adv1 [0,90)`、`adv2 [85,175)`……节目秒保留1位小数），只找四类低级错误（战斗中断 / 漏战 / 跑图残留 / 因果链断裂，标尺仍用 `complete-combat-roughcut.md` 第二层，不发明新标尺），风格/BGM/字幕字体/特效喜好一律不报。
- 对抗审与 §3.3 四验收角色（数字验收）同触发点、一次并行派出、互不等待；唯一阻塞点是推 vN+1——两边全部落盘并汇总成唯一问题清单后才开下一版，不边验边改线。对抗审禁改 `timeline/`、禁重渲、禁补抽帧定新边界，只写"问题 + 节目秒点 + 源秒换算 + 证据"；无问题结论必须附已看证明（抽帧规格 + 帧数 + 联系表路径 + 预算记录），否则判"未回"。
- 每路报告 `reports/adversarial_<任务>_vN_segK.md`（必填六节：区间 / 已看证明 / 问题清单 / 段缝互证 / 不报清单 / 末尾 `STATUS`；问题条目必填五项：类别 + `P→S` + 换算式 `S = episode.source_start + (P − episode.program_start)` + 画面描述 + 证据路径，P精确0.1秒）；汇总进 `accept_<任务>_vN.md` 对抗审章节（或独立 `adversarial_<任务>_vN_summary.md` 并在accept索引，全任务统一，重叠带按节目秒 ±2秒去重）。对抗审发现的战斗中断/漏战默认按大修处理。每路独立图片预算（成品抽帧同样计入AGENTS §9累计50张，单轮新增≤10，超量拼联系表）。

### 3.7 冻结门禁2.0（e5升级，来源 `123\workflow_upgrade\e5_freeze_gate.md`）

- 冻结定义五门AND：`冻结 vN ≡ G1 ∧ G2 ∧ G3 ∧ G4 ∧ G5`（G1数字验收四角全过 / G2全片密集扫零新增 / G3尾部逐段三信号确认 / G4预览对抗审零低级错误 / G5问题清单清零），任一FAIL即 `NOT_FROZEN` 推下一版，禁口头冻结，禁把 `needs_review` 悬挂带入冻结。
- 每版一张门禁检查表 `reports/freeze_gate_<序号>_vN.md`（与三分立同N同目录，模板见e5设计稿§2：版本基线 + 五门结论 + 尾部逐段附表 + 低级错误清单附表 + 总判；每格须带文件绝对路径 + 关键数字，只写"通过"无数字无路径视为未填，该门按FAIL计）。
- 零新增连续两版才送审：`streak` 定义为连续零新增版计数（G2与G4双零新增且G5清单为空，G1/G3通过为必要条件不计口径），`streak ≥ 2`（vN-1、vN连续两版）才送用户审片；`streak = 1` 判 `FROZEN（候选）` 须再跑一版完整复核；用户报障回来后 `streak` 清零重计。送审提交冻结三件套 + 现行预览 + 解码日志 + 自审/验收/复验 + 两版门禁检查表。
