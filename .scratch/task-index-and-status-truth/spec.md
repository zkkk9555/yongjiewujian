# Spec: 任务编号规则与项目状态如实化

**Status:** completed（2026-09-29）
**Lane:** B（文档修正，多文件，判据可逐条核）
**Gate 0:** MISS — 文档里既没有「最大编号 + 1」规则，也没有任何地方记录 848/852/853 目录已被删除。

## Problem

新开任务会拿到**错的编号**，也会拿到**错的现状**：

1. **编号规则自相矛盾且危险。** `123\README.md` §命名规则写「取 `123` 下下一个**未用**编号」，
   同一文件后面又写「下一个新任务编号从 **16** 起」。用户已明确否决这种写法：
   > 直接去看 1、2、3 这个目录里面，上一个的编号是多少，就接着往下排就行了。如果没有文件夹的话，那就从一开始排。

   危险是实打实的：已交付的 12/14/15 目录被手动删除后，盘上最大编号是 **13**。
   照字面「下一个未用」执行会取到 **14**，与已交付的素材 852 撞号。

2. **现状描述三重过期。** `README.md` 与 `123\README.md` 声称在制/已冻结任务为 12.848 / 13.849 / 14.852 / 15.853 四个目录；
   实测 `123\` 下只有 `13.849`。并称「848 与 852 尚未复制到 `E:\Cujian导出`，该目录当前只有 830–837 五个」；
   实测 `E:\Cujian导出\` 有 **16** 个成片，848（2882 MB）、852（2117 MB）、**853（1190 MB）** 均已就位。

3. **853 状态自相矛盾。** 文档称 853「未走门禁、无成片」，而 `E:\Cujian导出\853…cujian.mp4` 存在。
   这不是文案问题——一份未走门禁的成片进了交付目录，是门禁执行的事实，需要如实记录。

4. **依赖清单描述过期。** `config\production_dependencies.json` 的 `machine_tools.ffmpeg` 写
   `"WinGet link with resolved target"`，该安装已卸载。

5. **调用方式陷阱未记录。** 全项目文件带 MOTW + `RemoteSigned` ⇒ 文档里所有 `& '….ps1'` 写法都被拦。
   任务 849 的报告里全用 `powershell -NoProfile -ExecutionPolicy Bypass -File`，即该形式是实践中确立的，
   但没有一条文档写过。

## Solution

- 编号规则改写成用户口述的形式：**看现有目录的最大编号，+1；一个目录都没有就从 1 开始**。
  给出可直接粘贴的 `dir` 命令，让规则不依赖记忆。
- 把「任务目录会在交付后被手动删除」写成显式事实，并据此说明为什么**不能**按「未用」取号。
- 两处状态表改成实测值；`E:\Cujian导出` 计数改正；853 如实记为「有门禁外成片，已入交付目录」。
- 依赖清单的 ffmpeg 描述改成实测来源。
- `docs\TOOLS.md` / `docs\TROUBLESHOOTING.md` 补上 MOTW 陷阱与正确调用形式。

## Slices

- [x] **S2 状态如实化**：`README.md`、`123\README.md` 状态表与交付目录计数改为实测；

## Implementation Decisions

- **按 self-answer「历史行只追加、现在时指针必须说当前值」**：`README.md` 里 848/852/853 的历史行不删不改写，
  只把「现在时」的现状段改成实测值，并注明目录已由用户手动删除。
- **不写死「从 16 起」**：那是某一天的盘上快照，会再次过期。规则本身不依赖任何具体数字。
- **编号规则按用户口述原文落地，不擅自加东西**：用户明确否决了「下一个从 N 起」这类写死数字，
  要求"看现有目录接着排，没有就从 1"。故未引入任何台账文件。
  **已知残留风险（已写进 `123\README.md` 但未加机制）**：已交付目录被删后，`123\` 上的最大编号
  可能低于历史用过的编号（本例 13 < 15），新任务不会在磁盘上撞目录，但引用旧任务时要认准目录名前缀。
  若要根除，需要一个不随目录删除而缩水的编号台账——**未做，等用户决定**。
- **853 的门禁缺口不隐瞒、不代改**：如实记为遗留事实。是否补门禁是下一个任务，不在本轮。

## Testing Decisions

- 三条文档判据均可 grep 复核：规则句存在、过期计数串（`只有 830–837 五个`、`尚未复制`）在现状段消失、
  `WinGet link with resolved target` 从依赖清单消失。
- 文档给出的取号命令**实跑一次**，确认它输出的编号与盘上实况一致。

## Out of Scope

- 不动 `123\workflow_upgrade\`（skill 活引用，删除五步法明令不碰）。
- 不动 `assets\` / `feedback\` 空结构。
- 不清理 `.scratch\` 历史遗留（`run-832` 死指针等）：与工作流能否跑通无关，另议。

## Glossary

| 词 | 含义 |
|---|---|
| 最大编号 + 1 | 取 `123\` 下形如 `<数字>.<素材名>` 的目录中最大数字，加一即为新任务编号；无目录则从 1 起 |
| 交付目录 | `E:\Cujian导出`，成片的最终归属地，命名「源文件名 + cujian.mp4」 |
| 门禁外成片 | 未走 `freeze_gate` 门禁就已渲出并进入交付目录的成片 |
