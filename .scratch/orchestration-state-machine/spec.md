# 编排状态机：把「人守着」换成「脚本管」

## Problem

三局实测的耗时结构里，**46.5%（29.07 / 62.52 小时）是静默或纯等待**，而机器重活只占 3.1%。具体是三个洞：

1. **路被吞掉无人重派** —— 861 派 29 路，其中 3 路被服务端重启吞掉，**无人发现、无人换路、无人降级**，干等 **7.5 小时**。
2. **必须全回收才能合成** —— 规则 §2.3/§2.8 有岛式合并逃生阀，但被 §2.3 末句、§2.8 岛定义、§2.6 三处「partial 永不转正、渲染员禁认 partial」自己废掉，四局一次没用过（partial 文件数 = 0）。861 **26/29 路已回、盘上无成品**，干等 **9.3 小时**。
3. **授权后链路发呆** —— 「冻结完成 → 4K 真正开渲」空等 **6.57 小时**，其中 **≥85% 是链路没启动**（无编排脚本、无看门狗、无状态文件），不是真的在等用户。实测授权后整条链只要 16–25 分钟（863 16.5、864 24.5）。

共同的根因是**同一个**：编排状态只存在于 Agent 的对话里，盘上没有任何可重入的记录。

**台账的证据**：`123\21.864…\reports\dispatch_ledger.md` 表头只有 5 列（路 / 名称 / 状态 / 归属 / 摘要）——**没有派工时间、没有回收时间**。所以「这一路是不是卡死了」这个问题在盘上无解。

## Solution

一个约 300 行的编排层，三件事：

1. **状态文件** `reports\delivery_state.json` —— 阶段、每路的派工/回收时刻、重派次数、下一步。台账是它的**自动投影**，不是人工填的。
2. **看门狗** —— 超时判据 `clamp(3 × 本波已回收路时延 p50, 60, 240) min`，且须本波 ≥50% 回收才开火。命中即重派。
3. **流式合成** —— 回收一路合一路，出 PARTIAL 草稿，不再等全回收。
4. **授权后链路自跑** —— 授权仍由用户给；一旦检测到授权，链路自己跑完，不再空等。

## User-Stories

- **US1** 我派 14 路干活，中途服务重启吞掉几路，我希望**它们自己被重派**，而不是我干等到天亮。
- **US2** 我希望**看到一路回来就有一版能看的草稿**，而不是全部回来才有。
- **US3** 我说「输出 4K 成片」之后，希望**链路自己跑完**，不要停在那儿发呆。
- **US4** 我对话被打断后开新窗口，希望**5 分钟内能接着干**，而不是从头再来。

## Implementation Decisions

### 状态文件放 `reports\delivery_state.json`

`cleanup_after_master.ps1:59` 的 `$Disposable = @('preview', 'cache', 'shots', 'audio')` —— `reports\` 是保留区，状态文件放这儿不会被收尾清理删掉。

（860 曾有过已验证的 resume 实现，被清理脚本连同 `cache\` 一起删掉了。所以状态**不能**放 `cache\`。）

### 状态文件是唯一真源，台账是它的投影

理由：**Agent 不能给自己上闹钟。** 若让 Agent 自觉维护台账，861 有 29 行台账但实测全填字面 `T0`，而 `roughcut-launch.md §2.3` L70 要求的派工/回收时间列实测 0/4 局填上。脚本写，人读。

### 顶层 27 键，不做 104

02 号 Agent 最初设计 104 个具名字段，09 号裁决压到顶层 27 键。嵌套字段按需再加，顶层保持扁平可 grep。

### 「回收轮次 3 / 重派 attempt 2」拆成两个独立字段

09 号裁决：**这不是二选一**。「最多回收 3 轮」和「同一路最多重派 2 次」是两件事，一个字段表达不了。

### 超时判据必须要求 ≥50% 回收才开火

否则第一波慢路会被误判成卡死。回测：861 应在 19:35 换路（实际拖到次日 03:05，命中 7.5 h），864 零误杀。

### PARTIAL 草稿不能冒充成品

`wip` 预览放独立子目录，**QA/验收/冻结门禁按名与字段拒收**。
实测依据：今天**没有任何脚本在交付前调用 `qa_gate`**，720p 预览完全绕过 `read_episode_bounds.ps1` —— 所以拒收必须机械实现，不能靠自觉。

### 自动开渲已撤回，改成「授权后链路自跑」

实测 720p 预览 30 秒片段 **25.70 s**、4K **108.65 s**（慢 4.2 倍），换算 13 分钟成片：预览 11 分钟 vs 4K **47 分钟**。
**每渲一版 4K 要 47 分钟，而人看到才会想到改** —— 自动开渲等于每个版本白烧 47 分钟，一次返工就吃掉省下的 6.57 小时。
所以：授权仍是用户给，但授权一旦检测到，链路自动跑完（实测 16–25 分钟），治的是那 ≥85% 的发呆。

### 门禁不降级

冻结门 `streak≥2` **不动**。用户明确：宁可慢，不要一半时间拿到不能用的结果。
代价：效率目标从 5.1 小时上调到 **约 9.2 小时**。

## Out of Scope

- **改冻结门 `streak`** —— 用户否决（「标准不能降」）。
- **改 partial 禁令让它能转正** —— 用户没这个需求（只要验收过的成片，不要半成品）。
- **本地 VLM / OCR / 音效模型** —— #2 实测：kept-vs-deleted AUC 仅 0.723，逐集最低 0.015（反向）；音效模型 AUC 0.382，**方向反的**。装了会更糟。
- **换编排框架** —— #13 实测：LangGraph 要放弃 opencode 子 Agent；Temporal 要起 server 且换路仍得自写。opencode API 已给 wait/interrupt+resume/fork/revert/event 五个原语。
- **`#15` 渐进式交付** —— 用户要求等它回来再一起设计。**不猜。**
- **opencode.db 的 14.31 GB** —— 用户说不用管了。

## Glossary

| 词 | 含义 |
|---|---|
| **路（lane）** | 一次子 Agent 派工，负责一段素材的扫描 |
| **回收（recycle）** | 一路返回并落盘报告 |
| **PARTIAL** | 只并入已回收路的草稿时间线，**不是成品** |
| **WITHHELD** | 某项必需输入缺失，显式降级，**不许静默继续** |
| **水位线** | 状态机当前阶段 |
