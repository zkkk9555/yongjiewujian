## 四、矛盾有多真？——不是字面互斥，是「两条通道被写成了互斥」

### 4.1 字面比对

| | R1 要求主 Agent「看」 | R2 禁主 Agent「Read 任何图片」 |
|---|---|---|
| 字面是否互斥 | **否**，前提是「看」≠「Read 图片」 | — |

`R1` 说「看一遍成片」，`R2` 禁的是 `Read` 图片这个**具体工具调用**。
一个没有视频播放能力的 harness 里，「看完 561 秒成片」在物理上**只能**通过抽帧 → `Read` jpg 实现。所以：

- **字面：不互斥**（一个是义务，一个是手段禁令）。
- **可执行性：互斥**（在不违反 R2 的前提下，R1 对主 Agent 无法履行）。

这就是「不是字面互斥，但足以让人卡死」的那一类矛盾——比真互斥更难发现，因为它看起来像能两全。

### 4.2 三方对撞的真实形状

```
L128  累计 ≤50 张 / 单轮新增 ≤10          （上限，给所有人）
  │
  ├── R2 §2.1 L21  主 Agent = 0 张        （更严的下限，只给主 Agent）
  │      ✗ 与 R1 L163「自己看一遍成片」执行性互斥
  │
R1 L163  主 Agent 必须自查后才算完成        （义务，只给主 Agent）
  │
  └── R3「如有冲突以 50 张上限为准」        ← 兜底权
         它是**上限**，不是下限，本来不构成冲突；
         但它是「文档冲突时的最终裁决」，一旦 §2.1 与 L163 打起来，
         兜底权会落到 50，而 **50 ≠ 0**，等于把 R2 的下限被上限压平了。
```

**R3 真正的危险不是「不许复核 50」，是「兜底权没有作用域」。**
一个专门管**张数**的条款，被写成了**全项目文档冲突的终审**。R2 说的「0 张」是纪律，R3 的 50 是预算——两者不同量纲，被一句「如有冲突」强行放在一个天平上。

### 4.3 两全方案（不动预算机制）

把「看片」显式拆成**两条通道**，主 Agent 走 A、派子 Agent 走 B：

| 通道 | 手段 | 图片成本 | 谁做 | R2 是否违反 |
|---|---|---|---|---|
| **A · 零图片自查（必做）** | 解码日志、`blackdetect`/freeze、RMS/音频活动、`luma_probe.py` / `ui_probe.py` 数值、字幕跨段、切口表、**删除段语音战斗词扫描** | **0** | 主 Agent 本人 | 否 |
| **B · 定点目视（按需）** | 抽帧 → 联系表 → 单帧 ≤10 张 | ≤10 | **派「定点目视裁决员」子 Agent**，主 Agent 只读报告 | 否 |

**这不是发明，是项目里已经跑通、只是没写进规则的两条通道：**

- 通道 A 有实测资产：`861\reports\v3_problem_list.md` §F「**指挥零看图预算的数值实测**（`cache\luma_probe.py` / `cache\ui_probe.py`）」，F-1 把黑屏边界从 `[2322.1,…)` 修到 `2322.2`、F-2 把面板开合修到 0.1 秒级、F-3 排除 `-ss` 不可信 —— 全程 0 张图。`861\reports\tools\patch_spec_v7.py:99` 落款「指挥零看图预算独立复核通过」。
- 通道 B 也有实物：`864-rejected-attempt` 逮到漏战 E1 的手段，正是主 Agent 对 11 条删除段做语音战斗词扫描 —— `user_corrections_and_lessons_2026-10-01.md:126`「**本任务中，指挥正是用对 11 条删除段做语音战斗词扫描才逮到 E1 的**」，同一份文件 L138 记为「零图片成本，是逮到 E1 的唯一手段」。
- 通道 B 的现成角色已有：`864\reports\merchant_session_end.md` —— 合并阶段边界起争议时，指挥临时派了一路专职目视取证员（10 帧 960×540、落盘逐帧判读表）。**这个角色没有名字，也不在 §2.1 的 8 种角色表里。**

**一句话两全**：把 R1 从「自己看一遍成片」改成「**自己核一遍成片：零图片通道自查必做；需要目视的，派一路定点目视裁决员，自己不 Read 图**」。
R2 一个字不用改，R3 一个字不用碰，50 张机制不涉及。
