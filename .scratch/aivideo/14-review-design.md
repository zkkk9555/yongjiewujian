# 14 · 多路 Agent 审片的失效机制与异源交叉审查设计（2026-10）

> **调研角度**：本项目实测出「审片越多、共同盲区上越差」这个反直觉现象，2026 年有没有更好的设计？
> **方法**：arXiv 全文检索（2025-01 → 2026-10）+ 本项目文件实测复现。所有外部结论带链接。
> **标注约定**：`实测` = 本机跑出来的；`文档` = 有论文/官方文档原文；`推断` = 我的外推，需项目再验；`未找到` = 没搜到可靠来源，不编。

---

## 0. 一句话结论

> **同源 N 路的失效不是"模型不够多"，而是"信源不够多"**：它们的错误相关性天然很高，票数再翻倍也不产生新信息；而且**讨论/辩论会让它们更差**（自信的错误会把对的翻错）。修法不是加路数，是把**信源**换成互斥的：结构走代码、映射走集合运算、战斗性走语音与音频、被删内容走源片、观感走人眼。

## 1. 先确认现象是真的（`实测`）

### 1.1 门禁确实看不见"删掉一整场真战斗"

我用项目自己的 `qa_gate.py` 复现了 233 秒那个数字，并把结论固化下来：

- 素材 `combat_episodes_v6.json` 有 7 场，最长一场 `combat_009` = **233.45 s**（源 894.0 → 1127.45），占节目 35%。
- 把它整场删掉、同时**规规矩矩登记成一条 `deleted_intervals`**（保持 kept+deleted 铺满源片），跑门禁：

```
timeline_mutex        PASS   6 episodes ordered
source_range          PASS   6 in range
in_segment_holes      PASS   3 holes well-formed
no_holes_in_battle    PASS   no in-battle holes
no_zero_gap_pseudo_cuts PASS  6 episodes, no zero-gap cuts
coverage_complete     PASS   15 spans tile [0.00, 1152.23] with no gap > 0.25s
freeze_kit            PASS   1 files
→ pass=True  fail=0
```

**7/7 全绿。** 一场 35% 的战斗凭空消失，`qa_gate.py` 报 `pass=true`。

> 注：现版 `qa_gate.py` 已经多了一条 `coverage_complete`（docstring 里明写这是在 233.45 s 那次之后加的），它能抓**未登记的空洞**；但**抓不到"登记了却不该删"** —— 上面这次实测就是登记得干干净净的情况。

### 1.2 v1→v5 的冻结 JSON 缺陷逐字不变（`实测`）

用户说"四个致命缺陷在 v1 的时间线 JSON 里逐字存在，v1→v5 一个字节都没变"。逐版本比对：

| 版本 | 场数 | 段内挖洞 | 其中 <6 s | 保留总时长 |
|---|---|---|---|---|
| v1 | 11 | 1 | 0 | 630.00 s |
| v2 | 11 | 6 | 3 | 632.25 s |
| v3 | 11 | 10 | 7 | 630.93 s |
| v4 | 11 | **11** | 8 | **615.66 s** |
| v5 | 11 | 3 | 2 | 650.15 s |

- **E1（漏战）**：源 896–908 那场完整战斗，整段躺在 `deleted_intervals` `(810.0, 910.99)` 里，**v2/v3/v4 逐字相同**。
- **E2（战斗中被切断）**：`combat_003` 的 `source_start=357.0 / source_end=404.0 / outcome_time=398.0`，**v1 到 v5 五个版本一字未改**。

**而同期审片强度是峰值**：7 路对抗审 + 4 遍自审 + 3 路验收轮轮过。**门禁全绿 + 22 份对抗审全过 + 缺陷一个字节没动** —— 这三件事同时成立，说明"通过"这个信号本身在本项目里几乎没有信息量。

## 2. 文献侧：LLM-as-judge 的已知失效模式

### 2.1 同源重复投票为什么会失效

| 结论 | 证据 | 标注 |
|---|---|---|
| **多模型之间错误相关 0.529–0.689**，集成收益因此远低于 Condorcet 理论上限 —— 这是集成的**根本上限**，不是调参能解决的 | [arXiv:2605.30802](https://arxiv.org/abs/2605.30802)（多 Agent 预测市场裁决，1189 题） | `文档` |
| 同上，独立聚合+置信加权投票只比最强单模型高 **1.01 个百分点**（83.43%） | 同上 | `文档` |
| **辩论/审议式共识反而更差**：降到约 76%，低于每一个单模型基线，成因是"自信的错误模型把正确的翻错" | 同上 | `文档` |
| 多数投票的失败模式在个体都答对时也会发生；debate 在数学上可证优于静态集成 | [arXiv:2510.12697](https://arxiv.org/abs/2510.12697) | `文档` |
| **self-consistency 在现代模型上收益趋零**：HotpotQA 20 次采样只涨 **0.4%**，MATH-500 涨 **1.6%**，且高采样数时**反而下降** | [arXiv:2511.00751](https://arxiv.org/abs/2511.00751) | `文档` |
| 同上：多数投票**稳定优于**复杂的顺序修订与 mixture-of-agents 框架；存在"reasoning floor" | [arXiv:2504.14047](https://arxiv.org/abs/2504.14047) | `文档` |
| **更宽的采样只会重复已有答案模式，不增加有用多样性**；把算力用在"精修每条已有轨迹"上才有效 | [arXiv:2608.05643](https://arxiv.org/abs/2608.05643) | `文档` |
| 与人一致性中等，**不代表残差难度一致** —— 人和 LLM 觉得难的样本不是同一批，且强烈依赖评分维度 | [arXiv:2610.02877](https://arxiv.org/abs/2610.02877)（AACL-IJCNLP 2026，Rasch 模型分解） | `文档` |

**对应到本项目**：22 份对抗审的"票"全都投在**同一个信源**上。它们的错误相关性趋近 1，那么 Condorcet 上限趋近 1 路 —— **22 路的期望信息量约等于 1 路，再加上 21 次一致性背书**。而背书不是零成本：`streak≥2` 机制把"没人报"当"没问题"，**奖励沉默**。

### 2.2 独立评审、独立 Agent、独立提示词，能提高多少？

这是本次调研里**最反常识的一段**，三条互相独立的 2026 年证据都指向"几乎没用甚至有害"：

| 做法 | 实测效果 | 来源 | 标注 |
|---|---|---|---|
| **辩论式共识**（多 Agent 讨论后定论） | **低于每一个单模型基线** | [2605.30802](https://arxiv.org/abs/2605.30802) | `文档` |
| **人格设定（persona）prompt 多样性** | **准确率下降**。剂量-反应实验显示这是"人格税"不是"多样性红利"；冗余人格伤害最大 | [arXiv:2609.35875](https://arxiv.org/abs/2609.35875)（ICLR 2027 投稿，23 模型/11 厂商/5500+ 次运行） | `文档` |
| **换模型身份混编** | 混合模型团队**输给**自己名单上的多数投票；准确率跟随成员能力而非异质性 | 同上 | `文档` |
| 同样场景下，**首轮答案交换贡献了 debate 几乎全部收益** | 结构参数收益有限 | 同上 | `文档` |
| **多数压力压制独立纠正**；有效团队靠"推翻错误共识"，结构参数（顺序、置信可见）收益有限 | 主导因素是**内在推理强度与群体多样性** | [arXiv:2511.07784](https://arxiv.org/abs/2511.07784) | `文档` |
| MAD 在现有形式下**不可靠地优于** self-consistency 与多路径集成；只是对超参更敏感、更难调 | — | [arXiv:2311.17371](https://arxiv.org/abs/2311.17371) | `文档` |
| 创造性评估里 few-shot、集成、多 Agent 辩论**均无一致提升**；判读对 prompt 措辞敏感 | 换成可解释代理指标反而追平/超过最强 zero-shot 判官 | [arXiv:2608.30754](https://arxiv.org/abs/2608.30754)（EMNLP 2026 Findings） | `文档` |

> ⚠️ **注意这不等于"多路没用"**。同一位作者的对照实验里有**正面结论**：结构化人格设定（不是简单 prompt）确实产生了缩放性质，**分数随面板规模对数上升、但新问题发现服从次线性幂律**，且"分数饱和比发现饱和快约两倍" —— 即**加面板主要提升的是"发现问题"而不是"提升分数"**（[arXiv:2604.00477](https://arxiv.org/abs/2604.00477)，960 session）。这两篇不冲突：`2609.35875` 测的是**准确率**，`2604.00477` 测的是**发现新问题的数量**。对本项目而言，**我们要的是"发现"，不是"打分"**。

### 2.3 异源交叉审查（不同信息源）有没有方法论支撑

**有，而且这是本次调研里与本项目现状最贴合的一条。**

| 结论 | 证据 | 标注 |
|---|---|---|
| 判官面板应分三类角色：**copies（副本，加了不增加条件信息，可直接丢）/ complements（互补，全局有效，应加）/ specialists（专家，只在某类切片上有效，应条件路由）** | [arXiv:2608.19802](https://arxiv.org/abs/2608.19802)（WISE 2026） | `文档` |
| 该文明确给出可执行策略：**丢副本、加互补、条件路由专家、验证收益低于阈值就停** | 同上 | `文档` |
| 人类专家双评 + 分歧裁决产生金标准，再让 4 个本地 LLM 当判官：最高 kappa 0.803；但结论是"LLM 可以帮人类复核标注不一致，**专家验证仍然必要**" | [arXiv:2607.23312](https://arxiv.org/abs/2607.23312) | `文档` |
| 人格面板（心理多样 + 证据锚定）与人类判断相关从 r=0.716 → **0.922**；**纯 prompt 集成对照组只补回约三分之一**，说明增益主要来自"人格 + 证据锚定"而非"多跑几次" | [arXiv:2607.28439](https://arxiv.org/abs/2607.28439) | `文档` |
| 同上，并发现：子群体**总体排名一致、但具体维度上剧烈分歧** —— 这种结构性分歧是单一同质判官会**系统性抹掉**的 | 同上 | `文档` |
| 保留每个面板成员的**个体评分**（不只留聚合结论）是发现分歧的前提 | 同上 | `文档` |
| 混合异质判官 + 跨模型行为信号做"复杂度门控"，优于单纯增加辩论 Agent 数（后者只加数量不加多样性） | [arXiv:2603.12453](https://arxiv.org/abs/2603.12453)（SemEval-2026 Task 6，第 3 名） | `文档` |

**映射到本项目**：`stale streak≥2`（"没人报"当"没问题"）正是被上述文献一致判为**错误聚合**的那一类。它把"沉默"当成"干净"。而"丢副本、加互补"给出的正是可执行的组织原则：**22 路同源 = 22 个 copies，按这篇论文的分类应当全部丢弃。**

## 3. 提升判读独立性的已知手法

| 手法 | 文献怎么说 | 对本项目的可操作性 | 标注 |
|---|---|---|---|
| **角色分离（generator / critic 分离训练与部署）** | critic 若以"复现正确"为目标则无效，必须**显式优化成"超过生成器共识"** —— 反事实 critic advantage（reward 减生成器集成的逐样本正确率） | 现成可抄：审片员的任务书**禁止**看其他路的结论，且**必须**写出"我比冻结件多看见了什么" | `文档`（[arXiv:2607.18006](https://arxiv.org/abs/2607.18006)，MADA-RL） |
| **tutor-student 角色不对称交互** | 两个同模型的 Agent 分不对称角色，比 self-consistency / MAD / multi-agent review 更准或持平，**且 token 显著更少** | 抄"不对称"：裁决员不能与执行者同角色（本项目已有"裁决独立于执行者"的成功先例） | `文档`（[arXiv:2604.08931](https://arxiv.org/abs/2604.08931)） |
| **证据锚定（evidence-grounded）编排** | 混合"证据收集"与"推理"两阶段的架构，显著优于纯推理或纯前沿模型基线 | 每路必须先交**证据**再交判断；无证据的判断直接判未回 | `文档`（[arXiv:2607.20216](https://arxiv.org/abs/2607.20216)） |
| **盲评 / 隐藏归属标签** | 隐藏模型身份后 self-preference **消失**；一旦贴上 self/other 标签（哪怕是假的），分数**双向偏移**，投票结果最多可反转 50 个百分点 | 审片员不得知道"这是第几版""上一版改了什么""别的路怎么说" | `文档`（[arXiv:2608.18091](https://arxiv.org/abs/2608.18091)；[arXiv:2508.21164](https://arxiv.org/abs/2508.21164)） |
| **多模态输入（不同 modality 分路）** | 三 Agent 判官分解评估教学视频，可靠性**与人类专家中位数相当**；专家用它后 MAE 0.87→0.73，但专家仍能识别不可靠输出（AUC 0.77） | 每路用**不同模态**：字幕文本 / 音频波形 / 抽帧 / JSON —— 而不是同一批像素 | `文档`（[arXiv:2607.18529](https://arxiv.org/abs/2607.18529)） |
| **"有专业评分体系 + 学习者条件"的分层判官** | 评价质量依赖多模态证据，且应**相对于预期受众**评价，不是普适属性 | 同上 | `文档` |
| **显式 rubric / 判据** | 显式 rubric 能显著帮助模型在答案对之间保持一致（否则出现"情境偏好"）；但**对客观 rubric 仍有 >50% 的自偏好错误** | rubric 要写死；但**客观 rubric 也不得省掉异源复核** | `文档`（[arXiv:2512.16041](https://arxiv.org/abs/2512.16041)；[arXiv:2604.06996](https://arxiv.org/abs/2604.06996)） |
| **人类样本也要算方差，不能当金标准** | 同一篇发现**人类判断本身存在大量不一致**，所以"人类标注"未必是可靠金标准 | 用户审片也要当作**抽样探针**，不是判决 | `文档`（同上 [2512.16041](https://arxiv.org/abs/2512.16041)） |
| **多数压力会压制独立纠正** | 辩论中的多数压力抑制独立纠正 | **不要把"其他路都这么判"写进任务书** —— 这等于人工注入多数压力 | `文档`（[2511.07784](https://arxiv.org/abs/2511.07784)） |

**关于 fresh-start**：我**没有**搜到专门以 "fresh-start" 为名的、针对判读独立性的方法论论文。`未找到`。最接近的是"隐藏前置上下文/盲评"（[2608.18091](https://arxiv.org/abs/2608.18091)、[2508.21164](https://arxiv.org/abs/2508.21164)）与"面板中互不可见"。所以本项目若要"fresh-start"，**依据是盲评/标签隐藏，不是某个叫 fresh-start 的既有方法** —— 别在文档里编这个词。

## 4. 结构化校验 vs 语义评审：这条有强支撑

本项目自己已经发现"机械门禁应该完全交给代码"。文献支持非常明确：

| 结论 | 证据 | 标注 |
|---|---|---|
| **只要能确定性验证的任务，就不该用 LLM 判官** —— RLVR 只适用于数学/代码这类可确定性验证的域；开放式任务才被迫依赖偏好模型与 LLM 判官，后者引入**评估偏置、判官能力瓶颈、额外推理成本**三害 | [arXiv:2607.23802](https://arxiv.org/abs/2607.23802)（RLVR→RLSVR，COLM 2026） | `文档` |
| 可验证性可以**人为制造**：把开放式任务变换成"代理可验证环境"，由规则与交互结果自动产出奖励（SpyRL 用"谁是间谍"投票做完全可验证奖励） | 同上 | `文档` |
| 用**确定性符号验证器**（Lean 4 / Python）作为唯一奖励 oracle，可**消除 LLM-judge 的谄媚（sycophancy）** | [arXiv:2606.05030](https://arxiv.org/abs/2606.05030) | `文档` |
| 排序一致性**不等于**聚合量一致：33 组判官配置里 25 组排序准确率 ≥0.60，但可接受率估计从 **3.0% 到 97.9%** 乱跳（人类是 61.1%）；校准后仍最多只解释 **8.5%** 的个体方差 | [arXiv:2610.02492](https://arxiv.org/abs/2610.02492) | `文档` |
| 摘要类散文判读上，**简单可解释代理指标**（主题新颖度 / 上下文词聚类 / 词汇多样性）可**追平甚至超过最强 zero-shot LLM 判官**，成本低一个量级 | [arXiv:2608.30754](https://arxiv.org/abs/2608.30754) | `文档` |
| LLM 判官在人类验证的**已知失败集**上表现很差：GPT-4o-mini **批准了 47.9% 临床上错误的输出**，另一模型批准了全部失败样本 | [arXiv:2606.31608](https://arxiv.org/abs/2606.31608) | `文档` |
| 宽松的判定标尺会被**一致地执行成多个版本**（本项目：面板措辞偏差 → 7 人一致执行成 4 版）。文献侧对应"一条措辞偏差会被放大" | [arXiv:2604.22891](https://arxiv.org/abs/2604.22891)（认知负荷分解式多维评估降低自偏好 31.5%） | `推断`（文献讲的是评分偏置，我把它外推到"判读标尺措辞"，本项目 §4.4 已实测同一现象） |

**结论**：门禁不是"较弱的那层"，它是**唯一能保证可复现的那层**（见 §5）。语义评审只该做机器做不了的：**"这段是不是战斗"、"这波该不该留"**。

## 5. AI 评审的可复现性：同一份预览再审一遍有意义吗

**默认没有意义。** 这是本次调研里对本项目冲击最大的一条。

| 结论 | 证据 | 标注 |
|---|---|---|
| **temperature=0 不等于确定性**。实测真实评测代码库：判官未设 temperature/seed，provider 静默套用默认 **1.0**，边界附近的条目**在 20 次运行里逐条判定分歧最高约 50%** | [arXiv:2606.26185](https://arxiv.org/abs/2606.26185) | `文档` |
| **钉住 temperature=0 只能减少、不能消除翻转**：690 次 API 调用、2 个 provider、3 个模型档、5 种采样配置下，7 个边界条目里仍有 **1–2 个不可复现**，即使强制 greedy（top_k=1） | 同上 | `文档` |
| Claude Opus 4.7/4.8 **已弃用 temperature 参数** —— 主缓解手段对新模型代际失效 | 同上 | `文档` |
| 建议把**判官分歧本身当作一等健康指标**，与分数并列报告 | 同上 | `文档` |
| 判官可靠性两个维度都可用**无人类标注**的方式度量：局部自一致性（成对偏好稳定性）+ 全局逻辑一致性（传递性）；Gemini-2.5-Pro 与 GPT-5 在**近四分之一**的困难案例上无法维持一致偏好 | [arXiv:2512.16041](https://arxiv.org/abs/2512.16041) | `文档` |
| 用共形预测给 LLM-derived Elo 估计**分布无关的覆盖区间**，诚实表达"人机分歧不可消除的部分" | [arXiv:2606.13221](https://arxiv.org/abs/2606.13221) | `文档` |
| 顺序偏差（偏好后位选项）、**"表面反思偏差"**（模仿推理的措辞如"等等，让我想想"就能显著改变判定）、bandwagon / authority / distraction 偏差 | [arXiv:2504.09946](https://arxiv.org/abs/2504.09946) | `文档` |

**对本项目的直接含义**：
1. 「同一份预览再审一遍」如果只是**同一个模型、同一份任务书、换一个新会话**，其增信接近 0 —— 既不独立（同一信源），也不可复现（温度未钉）。
2. **"换模型"确实提高多样性**，但按 [2609.35875](https://arxiv.org/abs/2609.35875)，混编模型团队**输给**自己名单上的多数投票 —— 所以换模型的正确用法是**换信源**（换模态/换数据源），不是单纯换模型名。
3. 本项目能立刻落地的最小动作：**在审片报告里记录每路的判官分歧度**（同一份输入跑 2–3 次，看结论是否翻转），把"这一路的结论稳不稳"变成可读数，而不是默认它稳。

## 7. 异源审查分工表（本报告核心交付）

### 7.1 设计依据（一句话版）

> **独立 = 信源互斥，不是执行者互斥。** 判据可机械检查：**若路 A 的输入被删掉或伪造，路 B 的结论会不会变？不会 → A 与 B 是同一路，按一路计。**
>
> 方法论出处：`copies / complements / specialists` 三分（[2608.19802](https://arxiv.org/abs/2608.19802)）+ 错误相关性 0.529–0.689 的集成上限（[2605.30802](https://arxiv.org/abs/2605.30802)）+ 多数压力抑制独立纠正（[2511.07784](https://arxiv.org/abs/2511.07784)）。

### 7.3 派工硬规则（逐条可审计）

1. **信源唯一性**：X1…X8 输入源两两交集为空；每份报告头写「输入源清单 + 禁读清单」，缺一判"未回"。依据 [2608.19802](https://arxiv.org/abs/2608.19802) 的 copies/complements 分类。
2. **错误类别 ↔ 路由维度正交**：「漏战」**永远不按节目时间派工**（它没有节目轴坐标），只按 `deleted_intervals` 清单派（X2/X3）。这是本项目派工坐标系与断言坐标系的结构性错配。
3. **禁注入多数压力**：任务书里不得出现"其他路都判 X"。依据 [2511.07784](https://arxiv.org/abs/2511.07784)：多数压力会压制独立纠正。
4. **禁注入归属标签**：不得出现"这是第 N 版""上一版改了什么"。依据 [2608.18091](https://arxiv.org/abs/2608.18091)/[2508.21164](https://arxiv.org/abs/2508.21164)：贴标签即使造假也会双向偏移评分。
5. **证据先行**：每路先交证据（帧号/秒点/JSON 字段路径），再交判断；无证据的判断判未回。依据 [2607.20216](https://arxiv.org/abs/2607.20216)。
6. **保留个体结论**：不得只交聚合结论；每路的分歧要单独记。依据 [2607.28439](https://arxiv.org/abs/2607.28439)（子群体总体排名一致但维度上剧烈分歧，聚合会抹掉）。
7. **记录判官分歧度**：每路同一输入跑 2–3 次，结论翻转即标"不稳"。依据 [2606.26185](https://arxiv.org/abs/2606.26185)（temperature=0 也不可复现，边界条目 20 次运行分歧达 50%）。
8. **`streak≥2` 改判据**：不能用"没人报"当"没问题"。`未找到`支持这个具体机制，但 [2605.30802](https://arxiv.org/abs/2605.30802) 的路由建议（只自动放行**一致且高置信**的，其余升级人工）给出了方向：**streak 只用于"升级人工复核"，不用于"通过"**。
9. **不辩论**：不做多路讨论后定论。辩论在本项目语境下已被文献判为**低于每一个单模型**（[2605.30802](https://arxiv.org/abs/2605.30802)）。冲突时用**第三方裁决**（不同信源），不用讨论。
