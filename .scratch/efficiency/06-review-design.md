# 06 · 审片环节效率诊断：同源重复的根因与异源交叉审查设计

> **视角**：不看时间花在哪（01 号），不看串行点（02 号），不看返工分类（03 号），只看**审片这一环本身**——派了几路、每路看的是什么、那些派出去的注意力能发现什么。
> **输入真源**：`skills/naraka-highlight-studio\references\roughcut-launch.md` §2.1 / §3.1 / §3.3 / §3.6 / §3.7；`docs\lessons\archive\864-rejected-attempt\reports\adversarial_brief.md`（attempt-1 作业书原文）；`123\21.864…\reports\{dispatch_ledger,deleted_audit_v1,qa_gate_v1}.md`。

---

## 0. 一句话结论

> **审片不是路数不够，是所有路共用一个信源。** 22 份对抗审的输入是同一份冻结预览、同一批抽帧规格、同一份 `scanner_brief_common.md` 标尺 —— 它们的像素信息集完全相同，**第 N+1 路的新增量是措辞，不是证据**。而四类错误里有一类（漏战）根本不在预览里，于是 N 路一致地报了 0。**增信为零，负相关由此而来。**
> 修法：把「每版全片重跑 N 路同源」换成**8 路固定编制的异源交叉**（4 路零图读 JSON/音频/字幕/数值 + 4 路分属四种互斥信源），**首轮 +3 路、后续每版 −6 路、墙钟降约 2/3**，而可检出的错误类别从「1 类 × 1 信源」扩到「4 类 × 4 信源」。

## 1. 现行审片机制的结构性缺陷

### 1.1 作业书原文：同源是被**明文规定**的，不是执行失误

`864-rejected-attempt\reports\adversarial_brief.md` L3–4 / L38：

> 「与本版执行无关……你**只看冻结预览的内容**，按节目时间分段逐段看」
> 「从**预览**（不是源片）按节目秒抽帧，1fps 或 2fps，960x540」

`§3.6` 的切分规则同源：「按**节目时间**把冻结预览切成 60–90 秒/路」。

**「与本版执行无关」这条独立性纪律是对的、必须保留；错的是「独立」被实现成了「换一个会话窗口看同一批像素」。**
独立 = **信源互斥**，不是**执行者互斥**。attempt-1 的 7–8 路对抗审满足前者吗？不满足。

### 1.2 N 路同源 ≈ 1 路 + (N−1) 次一致性背书

同一份冻结预览、同一抽帧规格（1–2 fps / 960×540）、同一标尺（`scanner_brief_common.md` 第 5 节）下：

| 维度 | 路与路之间 |
|---|---|
| 像素信息集 | **完全相同**（同一 MP4、同一时间窗） |
| 判定阈值 | 相同（同一份作业书，且明令"不发明新标尺"） |
| 前置结论 | 相同（都读了同一批扫描报告，都带着"这场是战斗"的先验） |
| 新增量 | **措辞、详略、置信度** —— 无新证据 |

而在分歧仲裁上，措辞的仲裁规则是"谁描述得更有把握"，**不是"谁看见了新东西"**。
所以同源 N 路的信息论收益 ≈ 0，但**心理学成本极高**（见 1.3）。

### 1.3 派生三害：一致性被误当成正确性

| # | 派生机制 | 实证 |
|---|---|---|
| **① 「零新增 = 没问题」** | §3.7 `streak≥2` 用"没人报"当"没问题"的代理指标。一致性越高，streak 越容易达标 —— **机制奖励的是沉默** | 864-att2 v1 六路 adv 合计确认低级错误 **0**；attempt-1 v1 轮 8 路同样 0 |
| **② 错误获得免检地位** | 一条措辞有偏差的规则被 N 路独立确认后，它从"待验证"升级为"既定前提"，此后没人再质疑 | 面板措辞 → 7 人一致执行成 4 个版本；`rejoin_window 12s` → 6 版都用计时判据（03 号 §5.2 证据 3） |
| **③ 审得越多，错误被执行得越彻底** | 审查强度峰值处错误指标反向运动 | attempt-1 挖洞 **1→6→10→11**，节目 **−27.6 / −7.1 / −17.3 s**（多审一轮，多挖一点） |

### 1.4 深层错配：**按时间切段派工，但有一类错误没有时间坐标**

§3.6 派工维度是**节目时间窗**，错误清单却是**类别**。对四类错误逐条检验"能不能在指定时间窗内判定"：

| §3.6 四类 | 在节目时间窗内可判定？ | 说明 |
|---|---|---|
| 1 战斗中断 | ✅ 可以（在窗内找到一场战斗，看它何时消失） | — |
| 2 **漏战** | ❌ **不能** | 「源里有完整一场战斗，节目里没有」—— 这个断言的**证据在节目窗之外**。分段派工把每一路都钉在节目轴上，而漏战**没有节目轴坐标** |
| 3 跑图残留 | ✅ 可以 | — |
| 4 因果链断裂 | ⚠️ 半可以 | 突变在片内、来源在片外时不能 |

**结论：「漏战」这一类在「按节目时间切段」的派工方式下是结构性不可报的。** 这不是审得不够细，是**派工坐标系与断言坐标系不匹配**。
attempt-1 的 22 份对抗审，漏战命中 v1/v2/v3 **全为 0** —— 而源 896–908 那场完整战斗带着六条"它不是战斗"的书面取证躺在删除段里。

## 2. 「看预览永远发现不了」的错误类型（九类）

判据：**如果该错误的全部证据都不在预览这一份文件里，那么任何看预览的 Agent 都不可能发现它，与路数无关。**

| # | 错误类型 | 为什么看预览永远发现不了 | 实证 |
|---|---|---|---|
| **E1** | **漏战 / 删除段冤杀** | 被删内容不在预览里。作业书还明令"不读源片" | 源 896–908（语音 897.97「开始了」/ 901.80「弹太快了」/ 904.80「没事我杀了」）；22 份对抗审命中 0 |
| **E2** | **战斗中被切断（跨段归属错）** | 预览里那段战斗**就是断的**，而且断得很"干净"——没有黑场、没有卡顿，只是两段都成立。§3.6 类别 1「战斗中断」字面上覆盖了它，**但没有任何一路的作业书要求"数同一场战斗在节目轴上出现了几段"**：看图的人只看见一个断口，判断断口是不是"另一场"要靠跨段记忆，而这个记忆恰好是 60–90 秒分窗后必然丢失的东西。**可判定的做法是把每场战斗的源区间投影到节目轴、统计段数 —— 集合运算 + JSON，不是看画面** | `combat_003.source_end=404.0` / `combat_004.source_start=412.0` 在 v1 与 v5 被点名时**逐字节相同**；8 路对抗审轮轮漏过 |
| **E3** | **场首落动作中途** | 预览首帧"已经在开大/已经在打"，看起来像**正常开场**。只有拿源片同一区间横向对比才知道 3 秒前还在打 | `combat_009` 头=911.0（v1 自己的 notes 就写着"头落在上一场内"）；`combat_011` 头=1053.0 落在蓝白技能爆发正中间 |
| **E4** | **场边界假切口（0 秒间隙伪切口）** | 预览里两段首尾相接，看起来像一次正常切换 | `combat_005=[495.0,517.5]` 与 `combat_006=[517.5,556.5]` 在源上本就相接于同一秒 |
| **E5** | **删段分类错（面板读成战斗 / 战斗读成面板）** | 预览 960×540 下全屏面板遮住战场 → 判"无战斗"；面板又被删 → 更看不见。**循环证据** | v1 `[404,412)` reason 原文：「全屏 UI 无任何战斗信号…故判两场成立」 |
| **E6** | **因果断在未入片的那一段** | 预览只呈现状态突变的结果（倒地/复活/变灵魂），**原因链那一段在删除段里** | §3.1 第 4 遍自审视角针对的就是这个，但它要求"逐一要求来源战斗在片中"——**没有一路被派去看删除段里到底有什么** |
| **E7** | **门禁假 PASS / 工具误用** | 完全不可见。`blackdetect -af`（视频滤镜）让日志为空 → 结论为空 → 报告写"未检出黑场" → `preview_duration` 照样 PASS 一个用错滤镜渲出来的文件 | v4 `-af` 误用；程序化红像素把落日天空判成敌方血条（v1–v3）；帧秒偏移 +0.4667 s |
| **E8** | **字幕与时间线错位** | 画面无异，只有 `S = source_start + (P − program_start)` 的映射错、cue 跨段横跨、条数与 stats 不符 | §3.3-C 要求"字幕条数"但**只数条数**，映射正确性无独立信源 |
| **E9** | **纯数值错误** | 求和不符、episode 倒序重叠、`deleted_intervals` 漏登记 —— 与画面无关 | `program_sum` / `timeline_mutex` 是 `qa_gate.py` 已有的机械门禁，但**当前只有零图路做**，一裁就没人做 |

**九类里，只有 0/1/3 的"节目内跑图残留"与"接缝观感"是预览能自然承载的。**
换句话说：**现有 N 路同源审查，实质上只覆盖了九类中的一类半。** 这就是"审了 44 份审件一份没拦住"的算术解释。

## 3. 异源交叉审查：8 路固定编制

### 3.1 第一原则：信源唯一性（source-uniqueness）

> **独立性判据（可机械检查）**：若路 A 的输入被删掉/伪造，路 B 的结论会不会变？
> **不会 → A 与 B 是同一路，按一路计。**

因此每一路的任务书必须有两段清单：

```
【我的输入源】（只允许打开这些）
【我的禁读清单】（明确写出"禁止打开"的路径 —— 通常是别人的信源）
```

指挥汇总时做一次机械核对：**任两路的输入源清单交集必须为空**；否则判「同源重复」，该路的独立性不成立。

### 3.2 八路编制

| 路 | 角色 | **唯一输入源** | 覆盖对象 | 图片 | 拦哪类 |
|---|---|---|---|---|---|
| **R1** | **时间线结构审计员** | `timeline\combat_episodes_vN.json` + `program_map_vN.json` + `vN_validate.json` —— **禁止打开任何 mp4 / 任何帧目录** | 全表 100% | **0** | E2 跨段归属统计、E4 伪切口、E9 求和/单调/重复登记 |
| **R2** | **删除段独立信号审计员** | 转写 JSON + `analysis` 音频活动 + `scenes.csv` + `deleted_intervals` 的**起止秒** —— **禁止读 `deleted_intervals[].reason` 原文**（理由写得越详尽，盲区越深） | 每条 `deleted_intervals` 100% | **0** | **E1 漏战（语音/音频通道）** |
| **R3** | **删除段源侧目视反证** | **源片 960px 代理帧，按源秒抽**；只看删段，**不看预览、不看节目秒** | 每条 `deleted_intervals` 100%（>120 s 全段核验，≤120 s 按 1/5fps） | 每条 2–4 帧 | **E1 漏战（目视通道）**、E5 分类错 |
| **R4** | **预览内容审**（现有 §3.6 对抗审，唯一保留看预览的一路） | 冻结预览 MP4 —— **禁止读源片、禁止读 `deleted_intervals`** | 节目轴 `ceil(P/135)` 路 | 每路 ≤10 | 战斗中断、跑图残留、接缝观感 |
| **R5** | **源↔预览 差分审计** | 源片与预览**并排同一源秒区间**的高清帧 —— 禁止读 `program_map`（不许用映射表省事，必须目视对齐） | **只审全部场边界 ±5 s + 全部切口** | 每边界 2 帧 | **E2 切点选错、E3 场首落动作中途、E4 假切口** |
| **R6** | **字幕↔时间线映射审计员** | `captions\<序号>-review-vN.srt` + `.stats.json` + `program_map_vN.json` + **源转写原文** | 全部 cue 100% | **0** | **E8 错位/跨段横穿/条数不符** |
| **R7** | **数值与门禁取证员** | `qa_gate_vN.json` **重跑复算** + `ffprobe` + `validate` JSON + 渲染日志 —— 0 图 | 100% | **0** | **E7 假 PASS/工具误用**、E9 |
| **R8** | **复验核销员** | **上轮问题清单**（逐条）+ delta diff；**禁止重看全片** | 上轮问题 100% | 只看改动点 | 改动未达成其声明效果 |

### 3.3 派工硬规则（八条，逐条可审计）

1. **信源唯一性**：R1…R8 的输入源两两交集为空；每份报告头写「输入源清单 + 禁读清单」，缺一判"未回"。
2. **错误类别 ↔ 路由维度正交**：`E2/E3` 这类"在片内可见"的按节目时间切段派（R4）；`E1/E6` 这类"证据在片外"的按 **`deleted_intervals` 清单**派（R2/R3）。**「漏战」永远不按节目时间派工。**
3. **零图路优先派、优先回**：R1/R2/R6/R7 合计分钟级，必须先于任何取帧动作回，台账里先落它们的结论。
4. **R2 的 70 词战斗词表**不得复用现成 `combat_voice_index`（att2 实证：不采信现成词表、自建更宽的 70 词表才扫出 12 条命中）。
5. **R5 只审边界点**：不扫全片。它的成本是 `O(边界数)`，不是 `O(节目秒)`。
6. **R8 按"声明的目标"验收，不按"秒点变没变"验收**（att2 `workflow_notes_21.md §6` 教训：v2 的 881.0 改动只把货郎会话往后挪了 2 秒，**根本没删掉**）。
7. **R1 的两项统计必须写进报告**：① 每场战斗的源区间在节目轴上的投影段数（>1 即 E2 命中）；② 相邻场 `source_end == 下一场 source_start` 的对数（>0 即 E4 命中）。
8. **禁把"未报"计入通过**：R1–R7 各路必须附「已核证明」（覆盖清单 + 条数 + 路径），否则该路覆盖度判 0。

### 3.4 覆盖矩阵（可审计的对角线）

```
              信源:  JSON   音频   源片帧   预览帧   字幕   数值
  E1 漏战        ·      R2     R3       ×       ·      ·
  E2 战斗中切断   R1      ·      R5       R4*     ·      ·
  E3 场首中途     R1      ·      R5       ×       ·      ·
  E4 假切口       R1      ·      R5       ×       ·      ·
  E5 删段分类     ·      ·      R3       ×       ·      ·
  E6 因果断片外   ·      R2     R3       ×       ·      ·
  E7 工具/假PASS  ·      ·       ·       ·       ·      R7
  E8 字幕映射     R1      ·       ·       ·       R6     ·
  E9 纯数值       R1      ·       ·       ·       ·      R7
```
（R4 对 E2 只在"片内可见的截断"上有效，主判据在 R1/R5。）

**对角线非空 = 每一类错误至少有一路专属信源。** 这就是与现行机制的唯一、也是全部区别。
这张矩阵可以做成 `qa_gate.py` 里的一条 `source_uniqueness` 检查：读各路报告头清单，输出覆盖矩阵，**任一格为空即 FAIL**。

## 4. 成本估算：几路？多还是少？

以 864-att2 为标定素材（源 1152.2 s，节目 807.5 s，5 场，4 切口，6 条 `deleted_intervals`，96 cue）：

### 4.1 v1 一轮

| | 现行（att2 实测） | 提案 8 路 | 差 |
|---|---|---|---|
| 零图路 | **0** | **4**（R1 R2 R6 R7） | +4 |
| 图像路 | 8（6 adv + 1 自审 + 1 删除段审计） | 11（R4 × 6 + R3 × 3 + R5 × 2） | **+3** |
| 全片重跑像素量 | adv1 单路即 68 帧 → 6 张联系表，6 路合计约 40 张表 | R4 同量；R3 仅 14 张表/全程；R5 约 18 张单帧 | 基本持平 |
| 覆盖的错误类别 | 1.5 / 9 | **9 / 9** | — |
| 墙钟 | 扫描波 1.82 h + 审查波数小时 | 零图路分钟级 + R3/R5 各 ~20 min + R4 与现行同 | 持平 |

**首轮：多 3 路，换来覆盖类别从 1.5 类到 9 类。** 首轮不省，首轮买的是**把 v1 的结构做对**（02 号 §3.2 实证：循环次数 = v1 缺陷数，不是审查细致度）。

### 4.2 v2 及以后（delta 驱动）

| | 现行 | 提案 |
|---|---|---|
| 图像路 | 8–9（全片重跑）+ streak 强制第二版 | **2**（R3 只审变更的删除段 + R5 只审变更的边界） |
| 零图路 | 0 | 4（只在 diff 过的字段上重算） |
| 复验 | 逐条核销 | R8 逐条核销（**加强**） |
| 每版墙钟 | **小时级**（02 号 S2：冗余全片重扫 ~7 h；S4：streak +2–3 h/任务） | **分钟级** |

**后续每版：从 8–9 路降到 2 图像路（+4 零图路），墙钟降一个数量级。**

### 4.3 关键前提：R5 让"重跑"变成可判定的

现行之所以只能"全跑"，是因为**没有机制判断"这一版改了哪几帧"**。
提案把判据落成一条机械规则：

> 从 `program_map_vN` 与 `program_map_vN-1` diff 出变更的源秒集合 `Δ`。
> **R4 的一路 X 若其节目窗对应的源秒集合与 `Δ` 不相交 → 该路跳过（帧内容逐帧未变），落一句"本路内容未变，跳过"即闭环。**

这条规则有直接实证：**861 台账 L1796 自认「14 路对抗审所看的画面内容逐帧不变」** —— 规则只是把已经发生的事实自动化。
R3 同理：`deleted_intervals` 未变更则跳过。

## 5. 能砍掉哪些轮次？依据是什么？

### 5.1 砍四刀

## 7. 预判三条反对意见

| 反对 | 回应 |
|---|---|
| **「8 路不同信源会互相矛盾，仲裁成本反而更高」** | 现行同源 N 路的分歧发生在**措辞之间**（不可判定，只能比谁自信）；异源设计的分歧发生在**通道之间**（可判定：机器读数 vs 目视，有 `qa_gate` 兜底）。§3.7 的"定稿单人一次"照旧。**仲裁成本下降。** |
| **「零图路会漏掉画面问题」** | 会，但画面问题由 R3/R4/R5 覆盖，且零图路覆盖的正是**图像路结构上无法覆盖**的部分（不在片中的东西、映射、算术）。**两者是并集不是替代**：覆盖矩阵里 E1/E5 只有 R2/R3 一格，去掉零图路这部分直接归零。 |
| **「R5 要源片又要预览，成本翻倍」** | R5 的成本是 `O(边界数 × 2 帧)`，不是 `O(节目秒)`。864 标定：9 个边界 × 2 帧 = 18 张单帧 —— 不到 att2 删除段审计（14 张联系表）的一半。 |

## 8. 给决策者的一句话

> **同源重复的缺陷在于：N 路看同一批像素，第 N+1 路的新增量是措辞不是证据，而四类错误里「漏战」压根不在预览里 —— 于是增信为零、一致性反被当成免检、审查强度峰值处错误反向运动。**
> **异源交叉 = 8 路固定编制（JSON / 音频 / 源片删段 / 预览 / 源↔预览差分 / 字幕映射 / 数值门禁 / 核销），信源两两交集为空，覆盖矩阵每一格非空；首轮 +3 路、v2+ 每版 −6 路、墙钟降一个数量级。**
> **可砍：§3.7 streak 的全片实现（改零图路 delta streak）、§3.6 每版全片重跑（改 `Δ` 判据跳过）、四验收的逐版重复（合规改每任务一次）、四遍自审的逐版重复（纯微调版只跑第 1 遍）；须留并加强：v1 的全片预览审、核销轮。**
