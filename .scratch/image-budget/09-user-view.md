## 1. 方案 B 落地后，用户需要做什么

### 1.1 结论先行：**默认路径 = 一次点头，零配置。零重配成立。**

不是"理论上成立"，是本轮实测：

| 需不需要他做的事 | 答案 | 依据 |
|---|---|---|
| 填任何数字进配置？ | **不需要** | 上限运行时读（实测 `limit.input=524288`），已用运行时读，每图成本有 `default` 兜底 |
| 每次跑预算检查要传会话 ID 吗？ | **不需要** | **实测 `OPENCODE_SESSION_ID` 环境变量已在**（本轮实测值 = `ses_ef921e0e…`，与 `/api/session` 里最新那条 title「Image budget 9 user workflow」完全对上） |
| 换模型要改配置吗？ | **不用** | 08 §5 表已列 8 种换模型动作，7 种什么都不用改；本轮复核了最关键的一条：换 provider 也定位得到（键是 `providerID/modelID` 复合键） |
| 换到纯文本模型（40 个里 10 个）要记得改规则吗？ | **不用记** | `capabilities.input` 无 `image` → 自动 `[MOOT]` exit 3 |
| 要装包 / 改环境吗？ | **不要** | 宽高用 .NET 自带 `System.Drawing.Image`，符合 `AGENTS.md §2` |

### 1.2 唯一的一次性动作：**点一次头，5 秒，一句话**

要他授权的是**安全面**，不是配置面：

> **「让看图预算脚本读一下 `~/.config/opencode/service.json` 里的密码，
> 只用它连本机 127.0.0.1 问两个数（上限、已用）。不打印、不落盘、不外发。」**

- **为什么非他点头不可**：那是本机明文密码，Agent 去读它属于扩大信任面。规则本身不该替他做这个决定。
- **他实际要做的**：回一个「行」或「可以」。**没有第二个动作。**
- **他不需要知道他批的是什么细节**：只回"行"，Agent 负责做到上面那三条约束（只读、内存、不落盘）。
- **他要是不点头**：不是整个方案作废，退化成 `-Offline` 弱版本（只用 `config` 静态值），代价是上限和已用变成手填——
  这时**他才需要动手填两个数**，所以不批反而更麻烦。这条要跟他说清：**批了 = 零手工；不批 = 以后每次手填。**

### 1.3 两个**可选**加固，都不做也能跑（要跟他说"可以不批"）

| 可选 | 做什么 | 不做的后果 | 我的建议 |
|---|---|---|---|
| 标定 `image_cost` | 读 N 张已知尺寸的图，比对 token 增量，把 `confidence` 从 `unverified` 改成 `measured` | 永远保守（`max_of` 已消掉 7.4× 那个主导误差，剩下 0.1%–3.9%） | **先不做**。等真觉得"少看了图"再说，约 10 分钟 |
| 调大 `compaction.reserved` | 把 471,860 那道悬崖往外推 | 悬崖不动 | **先不做**。零代码但改 harness 配置，随时可撤 |

> ⚠ **注意这两个"可选"对用户来说是同一类东西：都是"以后再说"。**
> 如果落地文档把它们写成"步骤 3 / 步骤 4"，他就会以为还有 4 件事没做完。
> **正确写法是：默认路径只有 1 步（点头），后两个进"可选"表。**

### 1.4 落地后的零重配核实（他视角的四个换模型场景）

| 他做的事 | 他要改什么 | 他要知道的一句话 |
|---|---|---|
| 换个模型（同 provider） | **什么都不改** | 「上限自己会变」 |
| 换 provider | **什么都不改** | 「也是自动的」 |
| 换到不能看图的模型 | **什么都不改** | 「门禁会自己说'这模型看不了图，本条不适用'」 |
| 厂商改了图片计费 | **不用他改**——只有 Agent 改 `overrides` 一处 | 「厂商改价他自己会改表」 |

**他唯一需要记住的：什么都不要记。** 这比现在强——现在他得知道"50"这个数，
而"50"这个数在他这里已经过期了（01/04 已证它是旧网关产物，本方网关根本不公布图片上限）。

## 2. 用户该怎么知道预算状态

### 2.1 先否掉三种说法（这是本单最重要的设计约束）

| 候选 | 为什么不行 |
|---|---|
| 「本轮图片预估 12,340 tokens，占压缩线的 2.6%」 | **他看不懂也不关心。**项目里已有证据：他反复要求"全部用大白话"，`粗剪提示词.md:194` 明确禁了内部黑话（SEAM / G1–G5 / validate 实跑） |
| 「已用 412,000 / 524,288」 | 同上，且数字位数多到要数位数 |
| 「预算还剩 63%」 | 百分比是最抽象的表达。63% 意味着什么？他答不出来 |

### 2.2 他唯一有的直觉单位是「张」和「还能看多久」

`粗剪提示词.md` 里他对时间有非常成熟的直觉（"中间出几版我不在乎"、4K 授权闸门值 16 h 墙钟）。
但**对上下文容量他没有直觉**——这就是为什么"50"他能背而"471,860"他不会。

所以：**token 只允许出现在括号里，主语永远是「图」。**

### 2.3 三档灯色 — 这是他会用的说法（**Agent 说的话，不是他要说的话**）

| 灯 | 脚本 `status` | Agent 该说的一句话（逐字稿） | 要不要他回话 |
|---|---|---|---|
| 🟢 绿 | `PASS` | **什么都不说。** 写台账。 | 否 |
| 🟡 黄 | `WARN`（>60%） | 「**看图快到上限了，这轮我改拼联系表看。**」 | 否——**这是告知不是提问**，Agent 已经自己换了做法 |
| 🟠 橙 | `WARN`（>75%） | 「**上下文快满了。结论我都落盘了，我开个新窗口接着干。**」 | 否——**这仍然不是请求** |
| 🔴 红 | `FAIL`（exit 2） | 「**这个窗口的看图额度用完了。已看的都落盘在 `…`，我换窗口继续。**」 | 否 |

**四档全部不需要他回答。** 这是本节的核心断言，下面 §3 论证它为什么必须这样。

### 2.4 如果他主动问，有两种问法，各有固定答法

| 他说 | Agent 答（一句话，给张数） |
|---|---|
| 「还够看多少图？」 | 「够看 **120 多张** 960px 的，或者 **20 多张** 4K 静帧。」—— **给两个规格，因为他不知道这轮会抽什么尺寸** |
| 「看图预算还剩多少？」 | 「**充足**，这轮能看 100 多张。」/「**不多了**，这轮最多 20 来张。」—— 二选一，不给第三档 |

> **为什么给"张"不给 token**：`08 §4.3` 那张表换算出来是 ~157 张 960px / ~21 张 4K。
> 这两个数是他能直接用的——"这轮抽 30 张 4K 帧肯定爆，抽 6 张没问题"。
> token 数字对他零信息量。

## 3. 他最讨厌什么 → 打断原则

### 3.1 证据（全部是他自己写的，不是我推测的）

| 证据 | 出处 |
|---|---|
| 「中间出几版、推几轮我不在乎，**不要问我，不要分段汇报，最后一次性给结论**」 | `docs/粗剪提示词.md:27` |
| 「中间所有轮次只写文件（台账、notes、审计、门禁表、清理日志），**不要在对话里输出"本轮已推进／下一轮继续"这类过程话**」 | `docs/粗剪提示词.md:176` |
| 「一路跑到交付，不要中途停下来问我」 | `docs/粗剪提示词.md:169` |
| 「已经在快到接受不了的程度」（转述，仓内无原文记录） | 用户口头，见本次任务书 |
| **硬证据**：4K 授权闸门造成 **16.06 h 墙钟空等**，而实际编码只要 1.01 h（**15.9 倍**） | `.scratch/efficiency/05-time-to-first-preview.md:389` |

### 3.2 由此推出的原则（一条）

> ## **能自己解决的，写台账；解决不了的，一句话带方案来，不许空手来问。**

拆成三条可执行的判据：

| # | 判据 | 说明 |
|---|---|---|
| **P1** | **默认零打扰** | 绿灯连一句话都不许有。预算状态只进 `.scratch/image-budget/state/<sessionID>.jsonl`（08 §3.4 已设计）。**台账是写给他"事后查"用的，不是"实时播"用的** |
| **P2** | **打断的判据是「不可逆」，不是「紧张」** | 「快到了」不构成打断理由——它有自动解法（换窗口）。**已经丢了东西**才构成 |
| **P3** | **开口必须自带已做出的决定** | 允许说：「我换窗口接着干」。**禁止**说：「我要不要换窗口？」「你看这样行吗？」——后者把决策成本推给他，等于"分段汇报" |

### 3.3 什么情况下该主动打断（穷举，只有两类）

| 情形 | 该怎么做 | 为什么 |
|---|---|---|
| **A. 不可逆已发生**，且**没有**自动解法 | **立刻说，一句话，说清损失了什么、现在怎么补** | 例：压缩已经把帧换成文字摘要 → 那些帧的证据永久没了，必须让他知道哪一段结论不可回查 |
| **B. 需要他给一个只有他能给的东西**，且**不问他就动不了** | **一句话，把选择压到最小** | 例：他授权 4K（`粗剪提示词.md:143` 已把这句话登记成触发词）、他批准读凭据、他说"这个任务目录整目录删" |

**其余全部 P1 处理：写台账，最后一次性汇报时带一行。**

### 3.4 明确禁止的四件事（防止这条原则被执行歪）

1. ❌ **禁止新增中间汇报**。"预算还剩 40%"这种句子出现一次就是违规。
2. ❌ **禁止用问句收尾**。"……这样可以吗？"= 分段汇报的一种伪装。
3. ❌ **禁止把绿灯做成"贴心地报平安"**。他明确说过不要过程话，报平安也是过程话。
4. ❌ **禁止把台账做成需要他定期看的第二份东西**。台账的读者是**未来的 Agent 和事后的他**，不是当下的他。

## 4. 他说哪句话就能触发预算检查

### 4.1 先解剖项目已经形成的交互模式（这才是关键）

项目里已经有两个成熟的一句话触发器，形态完全一致：

| 他说 | 映射到 | 写到哪 | 何时回报 |
|---|---|---|---|
| 「**去收纳经验**」 | `scripts\collect_lessons.ps1` | `docs\lessons\POOL.md` | 汇报覆盖率与待升级清单 |
| 「**输出 4K 成片**」 | 整条交付链（渲染→验收→收尾清理） | `E:\Cujian导出\` + `reports\` | 全部做完，最后一次性给 |

共同结构（这是可复用的模式定义）：

```
一句自然话  →  一个脚本 / 一条已有链路  →  只增不改地落进台账或交付目录  →  最后一次性报
```

`POOL.md:5` 就是这个模式的样板：一句话写在文件顶部，脚本名紧随其后。

### 4.2 照着这个结构给预算的触发词

> ## **「查一下看图预算」**

选它的理由（逐条对着已有模式校准）：

- **和「去收纳经验」同构**：动宾结构、动宾都是口语、都是"去看一个已有的东西"而不是"去创建一样东西"。
- **不需要他记脚本名**：「去收纳经验」他也没记 `collect_lessons.ps1`；这句话里不带文件名，靠 `AGENTS.md §9` 映射。
- **和「输出 4K 成片」的关键区别要说清**：4K 那句是**授权**（解锁一条链路），
  「查一下看图预算」是**要一份现状**（只读、不解锁、不改任何东西）。
  **所以它不会像 4K 闸门那样空等**——因为它不 gate 任何后续动作。

**备选（都可用，但都不如上面这句自然）**：

| 备选 | 问题 |
|---|---|
| 「还能看多少图」 | 更像查询不像触发，且已被 §2.4 占用为"他问、Agent 答"的句式 |
| 「跑一下看图预算」 | 「跑一下」偏工程口吻，他不会这么说 |
| 「按预算看图」 | 语义是"设定"不是"检查"，容易和授权混淆 |

### 4.3 ⚠ 最关键的一条：**这句话是"我要主动看"，不是"你才可以跑"**

必须写进 `AGENTS.md §9`，否则会被理解成"不问他就不许跑"：

> 预算检查**默认每轮看图前自动跑**。「查一下看图预算」= 他想主动看现状，
> **不是**解锁开关。**没有这句话，检查照样跑。**

### 4.4 不建议把预算做成"像 4K 那样的授权闸门"

`.scratch/efficiency/05` 已经用 15.9 倍的墙钟代价证明：闸门空等是他的核心痛点。
看图预算**不需要他授权任何东西就能跑**，所以**绝对不要**把它做成 gate。
一旦做成 gate，它就变成第二个 16 h 空等。

## 5. 风险：他不知道有这套机制，会不会在别的对话里绕过

### 5.1 好消息：开新对话**不会**绕过——这一条已实测

**实测证据**：本轮（一个子 Agent 会话）的系统提示里，**`AGENTS.md` 全文被自动注入**，
其中 §9「单次图片上限」是完整的一段。所以：

> **只要他在 `C:\Project\永劫无间` 下开任何新对话，预算纪律就自动在场。不需要他记得任何东西。**

这是整个防绕过设计里**最强、且已经免费生效**的一层。**任何改动都必须保住它**
（也就是：不要把 §9 整段搬走、搬薄、或者改成"详见 IMAGE_LIMIT.md"——
§9 必须仍然**自足**，因为它是唯一被自动注入的那一份）。

### 5.2 真正的三个绕过口（按可能性排序）

| # | 绕过场景 | 为什么 AGENTS.md 挡不住 | 预防手段 |
|---|---|---|---|
| **R1** | **子 Agent 没拿到纪律** —— 864 那种 12 路并行，每路读自己的图 | 派工 prompt 是主 Agent 手写的，`AGENTS.md` **不会**自动注入给子 Agent | **派工模板 4 处各加一行**（`roughcut-launch.md` L68/90/106/159）：「本路看图前跑 `check_image_budget.ps1`，把 `status` 抄进报告」。**已实测子 Agent 是独立会话（50 个会话里 47 个有 `parentID`），父会话的预算管不到它们** |
| **R2** | **换了项目目录 / 换了 harness** | AGENTS.md 不注入 | 在**全局**记忆里留一句？**不建议**（项目纪律不该外溢）。可接受：出了这个项目就没有这套纪律，这是对的 |
| **R3** | **直接 `Read` 一堆图，跳过脚本** | 脚本管不了 harness 往请求里塞图（07 §2.4 已承认） | **事后 gate，不是事前拦截**：`qa_gate.py` 增一条——核对每份审片报告里有没有 `view_budget` 那一行；缺行就在**最后一次性汇报**里写「本轮有 N 路没跑看图预算」。**不中途叫停**（§3 P1） |

### 5.3 一条容易被忽略的绕过口：**子 Agent 各有各的预算（实测新发现）**

本轮实测：`/api/session` 返回 50 个会话，**47 个带 `parentID`**——
也就是这个项目里"一次对话"实际上是**十几个独立会话**，每个有自己的上下文和自己的压缩悬崖。

**这有两个用户侧后果，方案 B 必须承认**：

1. **好消息**：并行审片天然被切成了十几个小预算，**每路撞线的概率远低于"一个大会话看 90 张"**。
   05 号担心的"e4 极限并行叠上去"在 token 口径下**风险显著下降**。
2. **要提醒他的**：他心里的"这个窗口"和系统的"一个会话"不是一回事。
   主会话看不到子 Agent 的图，**主会话的预算绿，不代表子 Agent 绿**。
   → 所以 §4.3 那条"默认每轮自动跑"必须写成**"每一路都自动跑"**，而不是"这个窗口跑一次"。

### 5.4 预防手段的性价比排序（照 07 §4 共同前置算）

| 排序 | 手段 | 成本 | 挡住什么 |
|---|---|---|---|
| 1 | **`AGENTS.md §9` 保持自足 + 改成"跑这个脚本"** | 改几行 | R2 的一半、主对话绕过（**已自动生效，只要不破坏它**） |
| 2 | **派工模板 4 处各加一行** | 4 行 | **R1——实测这是最大绕过口** |
| 3 | **`qa_gate.py` 加一条事后 gate** | 中 | R3 |
| 4 | 全局记忆里提一句 | 极低 | R2，**但会造成纪律外溢，不建议** |

| **他要做的动作** | 无（但他以为自己在守一条会作废会话的红线） | **点头一次**（5 秒，授权读凭据） |
| **他看到预算提示的次数** | 0（现在根本没有） | **0～1 次**，且那一次是**告知不是提问** |
| **预算状态在哪** | 不存在 | 台账 `.scratch\image-budget\state\<sessionID>.jsonl`，**事后可查** |
| **他说的话** | 无 | 「查一下看图预算」（可选，主动触发） |
| **换模型** | 无所谓（反正数字是死的） | **无感**。上限和悬崖自动跟着变，34 个没有 `limit.input` 的模型门禁会自动变紧 |
| **新会话会不会失忆** | 不会（AGENTS.md 自动注入） | 不会（同样机制，且从"背一个数字"变成"跑一条命令"） |
| **真出事时** | 会话作废、换窗口（**已被证从未发生**） | 上下文压缩，**帧变文字、不可逆**——这才是他真正要防的，而 B 是唯一能防它的 |

**一句话总结变化**：从**信一条不知道还成不成立的数字**，变成**看一条会算的账**。
而他在这个过程里**只需要点一次头**。

## 附：给用户的三句话版本

1. **你要做的就一件事：说「行」，允许预算脚本读一下本机密码去问两个数（上限、已用）。**
   只读、不打印、不落盘、不外发。除此之外**什么都不用改**——换模型也不用改，数字是当场读的。
2. **落地后你不用记任何数字了。** 现在那个"50 张"其实已经过期（现在的网关根本不公布图片上限）。
   新版改成当场算账，而且**绿的时候一句都不跟你说**——只在真出事时说一句带方案的话，不会来问你。
3. **你说「查一下看图预算」就能看现状**，但这句话**不是开关**——不问他也照样每轮自动跑，
   包括每一个子 Agent 那一路（我实测子 Agent 是独立会话，主会话的绿灯管不到它们）。
