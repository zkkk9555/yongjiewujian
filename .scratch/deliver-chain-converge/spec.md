# Spec：交付链路收敛（乱码目录 / 成片只落 E 盘 / 收尾真删干净）

**Status:** in-progress
**Lane:** C（跨 5+ 文件、改变交付目标、引入新不变量）
**Gate 0:** MISS —— `scripts/` 与 v1.001 逐字一致，三个问题均未修；其它对话是**绕过**而非修复
（证据：`git status scripts/` 为空；任务 15.855 / 16.858 的成片是人工挪到 E 盘的）。

## Problem

用户实测：别的对话反复犯三个错，文档写了也没用。

### P1 乱码目录 `C:\Project\<乱码名>\` 反复出现

成因已坐实（码位比对）：某个 `.ps1` 存成 UTF-8 无 BOM，PowerShell 5.1 按 ANSI 读源码，
把中文项目路径读成 GBK 乱码，于是整棵目录树建到了项目外面。
现有防线是 `[WARN]`，**退出码仍是 0，Agent 直接忽略**，所以照旧复发。

### P2 出 4K 成片后，任务目录没真删干净

`cleanup_after_master.ps1:59` 的 `$Disposable = @('preview','cache','shots','audio')`
**不含 `deliverables`** —— 成片就住在 `deliverables\`，按设计被保留。这是我的设计错误：
用户要的终局是"任务目录只留几 MB 文本证据，成片只在 E 盘"。

实测现状（2026-09-30）：

| 任务 | 目录体积 | `deliverables\` 成片 | `E:\Cujian导出` |
|---|---|---|---|
| 13.849 | 2.55 GB | **2601 MB** | 也有，**重复** |
| 14.854 | 1.58 GB | **1617 MB** | 也有，**重复** |
| 17.859 | 1.94 GB | **1988 MB** | 也有，**重复** |
| 15.855 / 16.858 | 0.00 GB | 无 | 有（已正确收尾） |
| 18.860 | 7.29 GB | 无 | 无成片（仍在制） |
| 19.861 | 5.33 GB | 无 | 无成片（仍在制） |

重复占用约 **6.2 GB**。另 18.860 的 `timeline\` 里有 **614 MB 的 jpg**——
timeline 按约定只放 JSON，取证帧应进 `shots\`，属归档错位。

### P3 成片路径报错位置

Agent 报的成片路径是 `123\<编号>.<素材>\deliverables\<源文件名> cujian.mp4`，
而终局位置是 `E:\Cujian导出\<源文件名> cujian.mp4`。用户看到的就是"输出错目录"。
P2 与 P3 同源：渲染目标定错了。

## Solution

立一条**可强制的不变量**，让三个问题一起消失：

> **4K 成片只存在于 `E:\Cujian导出\`。任务目录里的 `deliverables\` 不得长期持有成片；
> 收尾清理必须先证明成片已在 E 盘落地且可解码，才允许删除本地副本与其余可再生重量。**

- **T1 乱码目录**：现有 WARN 升级为 BLOCKER（退出码 2），并给出可复制的一键清理命令；
  另加一个 `scripts\sanitize_stray_dirs.ps1`，按内容特征识别并清理。
- **T2 交付目标收敛**：渲染直出 `E:\Cujian导出\`；验收在校验后的 E 盘文件上做；
  收尾清理把 `deliverables\*.mp4` 纳入删除，并**先验证 E 盘成片存在且非空**，否则拒绝删除。
- **T3 文档同步**：AGENTS / README / WORKFLOW / 粗剪提示词 / skill / deliverables-and-qa 全部改成 E 盘口径。

## Implementation Decisions

- **渲染目标改成 E 盘，而不是渲完再搬**：搬运会多一份、多一次 4K 重写风险。
  改名规则沿用现成的「源文件名 + cujian.mp4」，与 `E:\Cujian导出` 现有 21 条一致。
- **收尾清理先验后删**：`deliverables\*.mp4` 删不掉，除非在 E 盘找到同名且非空的文件。
  这是防止"成片还没落地就把本地那份删了"的数据丢失护栏，优先级高于省磁盘。
- **野目录升级为 BLOCKER 而不是直接删**：删目录是破坏性动作，Agent 遇到 BLOCKER 应停下报告，
  由人确认后再跑清理脚本。项目铁律里"删别人的目录"本来就需要人点头。
- **不自动清理 18.860 / 19.861**：无成片，判定为在制任务，用户未授权。
- **不自动删除 849/854/859 的重复成片**：同样是破坏性动作，等用户点头。

## Testing Decisions

seam 锁在"真的发生了一次正确行为"，不是查文件内容：

1. 造一个项目旁野目录 → 预检必须退出 2 并点名该目录；清掉后回到 0。
2. 渲染到 E 盘的临时副本 → 成片落在 E 盘、任务目录 `deliverables\` 为空。
3. 收尾清理：E 盘有成片 → 本地 `deliverables\*.mp4` 被删、证据保留；
   **E 盘没有 → 拒绝删除并说明原因**（负向门禁，必须会拒）。
4. 四类可再生目录仍照旧删除，清理后卫生门禁仍 PASS，清理日志落盘。
5. 文档判据：全部提到成片路径的地方都是 `E:\Cujian导出`，不再有"成片在 deliverables"的说法。

## Out of Scope

- 不动 `123\18.860` / `123\19.861` 的在制内容（无成片，用户未授权）。
- 不自动删 849/854/859 的重复成片（破坏性，等授权）。
- 不动 `complete-combat-roughcut.md` 另一对话新增的「倒地—救援—复活因果链」条款——它与本轮无关，
  但会随本轮一起提交入库（它是未提交改动）。
- 不改字幕、剪辑判定、编码参数。

| 词 | 含义 |
|---|---|
| 交付成片 | `E:\Cujian导出\<源文件名> cujian.mp4`，4K 终版的**唯一**归属地 |
