# Spec: 任务编号顺位修复 + 防撞号分配器 + 编号规则升级

> 用户 2026-10-22 给了一张图：两个 `34.`（34.888 / 34.889）。
> 用户原话要点：①「能不能把它恢复成正常的顺序」②「万一哪时候我新对话开得太快了，
> 它们还会出现这种序号重复的问题」③「我剪辑了这么多素材，没有什么可以升级的东西吗？
> 如果是改这个序号的话，肯定是数字越大的素材往后排嘛」④「不要影响这个正常的项目的工作流，
> 把该改的地方都改一下，完善一下，升级一下」。

## Problem

**病根不是「取号算错」，是「取号没有分配器」。**

现在的规则（`123\README.md`）：看 `123\` 下最大编号，往后排 1。**这是一个「读」操作，
不是一个「分配」操作。** 两个对话挨着开，各自读到同一个 max=34，就各自建了 `34.X`。
而且 `scripts\check_task_numbering.ps1` 把撞号只判成 **NOTE**（不是硬违规），
所以撞号既不阻止发生、发生之后也不报警——两条保险都没有。

三个症状：

1. **34 重复**：`34.888`（03:38 建）与 `34.889`（03:35 建）共用编号 34。
2. **顺序不对**：按用户规则「数字越大的素材往后排」，应该是 888 → 889 → 890，
   而目录名是 34.888 / 34.889 / 35.890——中间那个挤了后一个的号。
3. **规则会复发**：只要两个对话同时开就会重演。

## Solution

三张切片（Lane B，≤3）：

| 切片 | 做什么 | 产物 |
|---|---|---|
| **S1 顺位修复** | 把 34.889 → **35.889**、35.890 → **36.890**，并把全仓（`123\` 树内 + 仓库文档）对旧目录名的引用同步过来 | 目录改名 + 约 1500 处文本引用同步 + 经验文件改名 |
| **S2 分配器** | 新建 `scripts\new_task_dir.ps1`：带锁取号、按素材幂等、单调递增、留索引、查素材倒序 | `scripts/new_task_dir.ps1` |
| **S3 门禁与文档** | 撞号从 NOTE 升成**硬违规**；新增索引一致性与素材顺序检查；改 `123\README.md`、`AGENTS.md`、`cujian` skill 的取号口径 | `scripts/check_task_numbering.ps1` + 4 处文档 |

## User-Stories

- **US1**：目录名一眼看过去是连续的：`13.849 … 34.888, 35.889, 36.890`，没有重复号，
  而且素材号递增。
- **US2**：以后开新对话**不可能**再撞号——不管开得多快。
- **US3**：同一个素材被两个对话同时开时，**不会**多出一个目录（复用同一个）。
- **US4**：撞号一旦发生，门禁立刻红（而不是像这次挂了一周没人管）。
- **US5**：现有工作流一点不变：剪辑流程、素材只读规则、收尾清理、经验池都不受影响。

## Implementation Decisions

### D1 · 顺位按「素材号递增」重排，落到 34.888 / 35.889 / 36.890

34.888 的号是对的（它本来就是 34），后两个顺延：34.889 → 35.889，35.890 → 36.890。
重排后 13…36 连续无洞、无重复。

### D2 · 引用同步是**全量文本替换**，不是逐个手改

`123\` 树内有约 1500 处文本命中旧目录名（分布在 1257+42+6+2 个文件与 251+3+2+1 个文件里），
绝大多数是报告里的绝对路径。手工改必然漏。
→ 一次性脚本按**扩展名白名单**（`.md .json .py .log .txt .ps1 .sh .srt`）逐文件做字符串替换，
**保留原 BOM 与行尾**（只替换子串，不动任何其它字节），并报出改了哪些文件。
二进制（jpg/mp4/pyc）一律不碰。

### D3 · 经验文件随目录号改名（门禁按目录号判名）

`34.889` 里的 `workflow_notes_34*.md`（32 份）→ `workflow_notes_35*.md`；
`35.890` 里的 `workflow_notes_35.md` → `workflow_notes_36.md`。
否则 `check_task_hygiene.ps1` 与 `collect_lessons.ps1` 会立刻判不合规。

### D4 · 分配器 = 锁 + 幂等 + 单调 + 索引

`scripts\new_task_dir.ps1`（新）：

1. **锁**：对 `123\.seq.lock` 取独占句柄（`FileShare::None`），拿不到就等（默认 30 秒）。
   两个对话同时开 → 一个拿到号，另一个等它算完再算，**必然拿到不同的号**。
2. **幂等**：先按素材名（去扩展名后比较）找已有任务目录；找到就**直接返回那个目录**
   并打印 `REUSE`——同一个素材开两个对话不会多出目录（US3）。
3. **单调**：新号 = 现有最大编号 + 1；若该号已被占用（极小概率的残留）就 +1 重试，上限 100 次。
4. **索引**：写一行到 `123\index.tsv`（编号⇥素材⇥创建时间⇥备注），可查「哪个素材在哪个目录」。
5. **素材顺序**：比较新素材号与当前最大目录的素材号；若变小，打印醒目 WARN
   「素材号倒序：xxx 排在 yyy 之后」——用户的规则是「数字越大的素材往后排」，
   倒序时要让人看见（但不阻塞：历史已定，不能重排）。

### D5 · 撞号升级为硬违规

`check_task_numbering.ps1`：同一编号被多个目录占用 → **VIOLATION**（退出码 1），
不再只是 NOTE。理由：编号唯一是 `123\README.md` 的明文规则（每个目录占用一个编号），
而这次撞号之所以挂了一周，就是因为它不报警。
（连带：正文里那句「[PASS] 编号唯一」的老措辞也随之作废，改为按实情分两种说法。）

### D6 · 不动的东西

- ~~不改任何成片（E 盘 40 份 mp4 一律不动；母版按**素材名**命名，与任务目录号无关）。~~
  **2026-10-22 后续修正**：用户追问「884 导出的成片名字也有问题」后，**884 的母版名被改了**
  （`884永劫无间 2026-10-09 18-12-51.mp4 cujian.mp4` → `884永劫无间 2026-10-09 18-12-51 cujian.mp4`，
  7 处引用同步）。理由：母版名按约定是「源文件名**去扩展名** + ` cujian.mp4`」，
  884 那个名字里的 `.mp4` 是建目录时没去扩展名一路传染下来的，属于**错的**。
  改名只动 E 盘上的文件名（内容一个字节没变），其它 39 份母版一律未动。
- ~~不改 `30.884…mp4` 那个带扩展名的历史目录名（98 处引用；另立一轮处理）。~~
  **2026-10-22 后续已改**：用户追问「名字为什么有问题」后查明病根是**建目录时没去扩展名**
  （不是素材有问题——源片真名 `884永劫无间 2026-10-09 18-12-51.mp4` 是正常的），
  于是目录名纠正为 `30.884永劫无间 2026-10-09 18-12-51`（411 处引用同步），
  E 盘母版名纠正为 `884永劫无间 2026-10-09 18-12-51 cujian.mp4`，
  并加门禁 `check_task_numbering.ps1` 的 `DIR_HAS_EXTENSION`。
  分配器（`new_task_dir.ps1`）天生不会犯这个错——它内部就去扩展名。
- 不改剪辑流程的任何判据（`complete-combat-roughcut.md` 等本轮只新增一条纪律，不动旧条）。

## Testing Decisions

- **T1 顺位**：改完后 `123\` 里 24 个目录的编号集合 = {13..36} 无重复无洞；
  `check_task_numbering.ps1` 退出码 0 且不再有 DUP_NUMBER。
- **T2 引用完整性**：全仓 grep 旧目录名 `34.889永劫无间` / `35.890永劫无间` = **0 处活路径引用**
  （例外两处**故意的历史记录**：`docs\TROUBLESHOOTING.md` 的事故叙述里原样引用了旧名，
  以及 `123\35.889…\scripts_local\_fix_stray.py` 里指向另一个**时间戳打错一位**的野生目录
  `34.889…22-11-15`，那不是本次改名对象）；
  新目录名命中数 > 0（证明替换确实发生了，不是「没找到所以没改」）。
- **T3 经验池**：`collect_lessons.ps1` 待升级仍为 **0**（证明 POOL 的来源键跟上了改名）；
  命名不合规 0；缺 notes 0。
- **T4 卫生门**：`check_task_hygiene.ps1` × 24 个目录 = 0 失败。
- **T5 分配器（红绿）**：
  - 红：模拟两个并发进程同时取号 → 必须拿到**不同**的号；
  - 绿：同一个素材连跑两次 → 第二次必须 `REUSE` 同一个目录，不新建；
  - 绿：新号严格大于现有最大号；`index.tsv` 有对应行。
- **T6 门禁能抓**：造一个撞号（临时目录，超门禁范围）→ 脚本必须退出码 1 且报 DUP_NUMBER；
  测完即删。
- **T7 预检**：`check_video_environment.ps1` 退出码 0（它会调编号体检）。

## Glossary

- **任务目录号**：`123\<编号>.` 的那段整数，只增不重置，与素材号（文件名开头的 888/889）无关。
- **素材号**：素材文件名开头的整数（888、889、890）。
- **分配器**：`scripts\new_task_dir.ps1`，唯一合法的建任务目录入口。
- **索引**：`123\index.tsv`，编号⇥素材⇥时间⇥备注。
