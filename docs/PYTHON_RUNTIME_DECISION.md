## 一、用大白话说发生了什么

项目里有个共用的 Python 工具箱（`.video-tools\venv`），装着三个干活的家伙：

- **faster-whisper** —— 把游戏语音转成文字（字幕）
- **PySceneDetect** —— 找画面切点
- **Auto-Editor** —— 找有声音/没声音的区间

这个工具箱是用一个**临时下载的 Python** 装出来的。那个临时文件后来被系统当垃圾清掉了。

现在的状态有点坑：

- 工具箱里的文件**都还在**（27 个入口都在，`python.exe` 也在）；
- 之前那个自检脚本只检查「文件在不在」，所以它报的是 **一切正常**；
- 但真的一让它干活，它**起不来**。

所以：**字幕功能现在是废的。** 模型权重（large-v3 等）本身没丢，丢的是"跑起来"的那个零件。

全机也找不到别的能用的 Python——PATH 上那个 `python` 是微软商店的占位壳，一运行就提示"请从商店安装"。

## 二、这会怎么影响你

| 影响 | 说明 |
|---|---|
| **字幕做不了** | 三个工具全部不可用 |
| 画面/音频分析不受影响 | FFmpeg 还能用（走 LosslessCut 内置那份 n8.0），剪辑、渲染、成片都不受影响 |
| skill 自带校验脚本跑不了 | `validate_combat_timeline.py` 这类需要 Python 的脚本不可用；历史任务 848/849 已经手工改写成 PowerShell 顶替 |
| 门禁会打折 | 冻结检查里和字幕相关的项会变成"不适用"，不能再声称"完整通过" |

**注意：粗剪本身还能做。** 848 和 852 都证明过，字幕空着也能出片。修 Python 是为了把能力补回来，不是"不做就做不了"。

## 三、三个选项

### 选项 1：授权修复（推荐）

装一个**稳定的、不会凭空消失的** Python，然后用项目里已经锁好的版本清单把工具箱重建回来。

- 做什么：装 Python → 重建 `.video-tools\venv` → 按 `config\production_dependencies.json` 装回指定版本（faster-whisper 1.2.1、scenedetect 0.7.1、auto-editor 29.3.1 等）→ 跑预检转绿。
- 得到：字幕、三件分析工具、skill 自带脚本，全部恢复。
- 代价：需要联网下载；装包大概几分钟到十几分钟。**这是对机器的外部可见改动**，所以必须你点头。
- 风险点：这次要确保基础 Python 装在**正常位置**（比如 `C:\Program Files\Python313`），不要再挂在任何临时缓存目录里，否则会重演今天这个坑。

### 选项 2：接受降级，不修

- 做什么：什么都不改，粗剪走视觉 + 音频信号，出无字幕预览。
- 得到：零成本、零风险，今天就能继续干活。
- 代价：永远没有字幕；门禁里字幕项永久标"不适用"；skill 自带 Python 脚本继续不可用。
- 适用：如果你本来就不太看字幕。

### 选项 3：换基座

不修 Python，把工作流正式改成"PowerShell + 自带 FFmpeg"路线，把 whisper 从**必需**降为**可选增强**。

- 做什么：重写 skill 里依赖 Python 的环节，用 PowerShell 实现（历史任务 13 已经这么试过一次）。
- 得到：不依赖 Python，基础更稳。
- 代价：工作量最大；PowerShell 版本性能和可维护性都不如 Python；部分分析能力会缩水。
- 适用：如果你觉得 Python 环境反复被系统清理、不可靠。

## 四、我的建议

**选 1，但装到稳定位置。**

理由：今天的故障根因不是 Python 本身有问题，而是它被装在了**临时缓存目录**里，系统一清理就没了。只要装到 `C:\Program Files` 这种正常位置，同类故障不会再犯。而且三个工具的能力是实打实有用的——尤其字幕。

如果你其实不看字幕，**选 2** 也完全合理，能省下下载和等待的时间。

**选 3 除非你明确 wanting 摆脱 Python 依赖，否则不推荐**——它成本最高、能力损失最大。
