## 0. 审片基线与两条方法学校正（先说，影响后面所有秒点）

### 0.1 预览实体（`ffprobe` 实跑，非引用）

| 项 | 实测值 |
|---|---|
| 容器 / 视频流时长 | 580.304333 s |
| 分辨率 / 帧率 | 1280×720 / `r_frame_rate` = `avg_frame_rate` = **60/1（CFR）** |
| `nb_frames` | **34 817**（= 580.283 × 60，与 `program_map_v3.json` 20 个 cut 的 `rendered_frames` 合计一致） |
| 流数 | **2**（idx0 video / idx1 audio）→ **0 条 subtitle 流，干净画面** |
| 视频 `start_time` | **0.021000 s** |

**由此钉死时间基准**：帧序号 `n`（0 基）的**节目时间 = n/60**，其容器 pts = `n/60 + 0.021`。
本报告所有节目秒一律按 `n/60` 给出；「节目 P」指**画面内容时间**，不是容器 pts。
（`audit_brief_v3` 的抽帧命令烧 `%{pts\:hms}`，在 `-ss` 前置时输出 pts 从 0 重启，因此我用自己的 `mk.ps1` 用 `setpts=PTS-STARTPTS+$Start/TB` 把绝对秒烧进画面，见 §6。）

### 0.2 校正一：`-frames:v` 而不是 `-t`

作业书推荐的 `-ss A -i SRC -t D` 在我实测中**只在 `-t` 之前没有别的时移滤镜时成立**。一旦滤镜链里出现 `setpts=PTS-STARTPTS+$Start/TB`（把输出时间轴整体平移到绝对秒），**`-t D` 会按平移后的时间轴截止，等于什么都不输出**（实测 `frame=0`、`Output file is empty`）。
正确写法（本报告全部采用）：`-ss A -i SRC -vf "...setpts..." -fps_mode passthrough -frames:v (D*fps)`。见 `shots\adv3r2\mk.ps1`。

### 0.3 校正二：`trim` + `setpts` + `rawvideo` 会产生「补零帧」，但索引仍等于帧号

`trim=start=A,setpts=PTS-STARTPTS+A/TB ... -f rawvideo` 会让 rawvideo 复用器按 CFR 从 0 开始补 `A×60` 个重复帧（ffmpeg 报 `dup=8220`）。
**补零帧数恰好等于 A×60，因此「文件索引 = 全片帧号 n = 节目秒 ×60」成立**，可直接用下标定位到帧，不必再做偏移修正。
我用 `cut120_60.gray` 交叉验证过：全帧率帧差尖峰落在索引 7231 = 节目 **120.5167**，与 `program_map_v3.json` 的 `program_start = 120.5` 逐帧吻合。

### 0.4 校正三（对 v2 文档的算术更正）

v2 自审 **s2** 写「`P 139.5`（源 375.5）」。按 `combat_episodes_v3.json` 的换算式 `S = 357.0 + (P − 120.5)`，**P 139.5 = S 376.0**，不是 375.5。
