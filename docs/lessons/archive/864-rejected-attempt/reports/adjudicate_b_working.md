## 零图片预算的客观检测器

venv 无 PIL，故自写 `shots\adjudicate_b\barfind.py`：ffmpeg 解码 → rawvideo rgb24 → numpy，
逐行找**长度 ≥40px 的饱和红/蓝水平连续段**并报 bbox。

理由（对照作业书 §5 判定标尺）：敌方血条 = **宽而薄的水平红条 + 名牌**；
常驻 HUD（队伍名册、魂玉计数、播报栏）同样是红/蓝水平条，**必须用几何 + 时间规律把它和敌人血条分开**，
不能靠肉眼在联系表上猜。

## 方法论踩坑记录（第 4 个坑，作业书未列，建议补进 cache 脚本注释）

`crop_sheet.ps1` 第一版用 `ffmpeg -i SRC -ss T -frames:v 1` 单帧抽取，
**对 6 个不同 T 返回了同一帧画面**（6 个输出 MD5 不同只因裁切偏移不同，内容逐像素一致）。
→ 这是作业书坑 #1「输出侧 seek」的**变种**：单帧 + `-frames:v 1` 时输出侧 seek 在本机 4K 源上不可靠。
**修法：所有放大裁切都从已抽好的、MD5 已校验的帧文件里裁**（`make_route_frames.ps1` 产物），
并在脚本里加 `Get-FileHash` 去重断言，重复即 `exit 2`。已实现并生效。
