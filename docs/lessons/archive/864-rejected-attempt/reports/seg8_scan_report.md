## 0. 工具链与取帧方法（先记，因为它影响所有时间戳可信度）

### 0.1 预置材料的两个坑（已查清，结论：文件名可信）

1. **烧字与文件名一致，无偏移。** 作业书说"文件名即源秒，左上角烧 h:mm:ss"。我一度以为 `hd\t0595.0.jpg` 烧的是 `00:10:00`（600 s，差 5 s），
   因为 4x4 联系表缩到 1920x1080 后烧字只有十几像素、极易读错。**用 960x540 原图放大核对后确认烧字就是 `00:09:55.000`，与文件名一致。**
   → **全 seg8 时间戳一律以 `hd\tXXXX.0.jpg` 的文件名为准。**
2. **`cache\make_route_frames.ps1` 在本机 ffmpeg 上产出重复帧，不能用。** 作业书 §2 说"已修好，用 `-t` 即可"，实测不成立：
   - 跑 `-SegStart 592 -SegEnd 600 -Fps 1` → 输出 **600 个字节完全相同**的帧（MD5 全等），且张数 = `1152-592`，说明 `-t` 没限住。
   - 逐步二分定位：`-ss 592 -i src -frames:v 3`（无滤镜）→ 3 帧**互不相同**（正常）；
     加 `fps=1,...` → 3 帧全等；加 `scale,setpts=PTS+592/TB,drawtext`（无 fps）→ 8 帧全等。
     → **本 ffmpeg（n8.0-23）里 `fps=` 与 `setpts=` 都会把 input-`-ss` 后的流压成重复帧。**
   - 可用配方：**`-ss <秒> -i <src> -frames:v 1`（每秒一次调用）**，源是 CFR 60fps，秒级寻址帧精确。
     我把它写成 `shots\seg8\verify\grab.ps1`（ASCII-only，自带 592+ 校准帧可复现）。
   - **这条要回给指挥**：`make_route_frames.ps1` 的"已修好"结论在当前 ffmpeg 上是错的，
     任何扫描员拿它抽密帧都会拿到一堆重复帧，然后据此判"无战斗"——会成片误删。

### 0.2 全帧 PSNR 在本素材上不可用（记下来省别人踩）

拿 `hd\t0595.0.jpg` 跟 `hd\t0596.0.jpg` 比，全帧 PSNR 只有 **18.5 dB**；我自己抽的 t0595 vs t0596 也只有 17.9 dB。
原因是镜头一直在动、主体只占画面一小块，PSNR 被背景主导，**任何一对都是 16–19 dB，没有区分度**。
我又试了 32x32 灰度归一化互相关（NCC，`verify\ncc.ps1`）：同一素材相邻帧也只有 0.17–0.19，t0595 拿到 0.4155，
峰值方向对但绝对值不可信（整段都是"粉红天空+残垣+草地"的同质画面）。
→ **本素材判定边界只能靠人眼看帧，不能靠像素相似度自动对齐。** 下面的结论都是看图结论。
