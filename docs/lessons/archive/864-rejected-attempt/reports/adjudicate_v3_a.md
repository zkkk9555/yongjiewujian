## 2. 三个问题的裁决

### 问题 1：`S 305.0 → 318.3` 到底是什么性质？分界秒点？

**裁决：整段 `S 305.0 → 320.266` 全部是「无目的跑图 / 纯位移」，该删。分界帧 = `n = 19216`（`S = 320.267`）。**

理由（三条独立、互不依赖）：

1. **画面三信号全程为零（4K 帧级）**：`S 305.0 → 320.25` 内**没有任何敌方红血条、没有伤害数字、没有锁定线**。10 fps × 4K 全带扫描在 `x ≥ 0.22w` 的整个上带里，唯一够格的实心条首次出现在 `n = 19216`；60 fps 复核 `S 319.50 → 320.25`（`f60\`，121 帧）**一帧 HUD 条都没有**。
2. **内容形态就是位移**：瓦顶滑行 → 空中滑翔（309 绿勾锁弹道）→ 地面奔跑 → 「落印粉末」传送演出（317 灰雾 / 318 近黑）→ 下坠落场。按 §5.1「钩锁/御空/蓝盾类位移特效不得单独作为交战证据」，这一串**一条都不算数**。
3. **转写不构成反证**：`source_transcript.json` 在 `S 305 → 331.65` 只有三句——308.28「还追吗」、314.66「我去」、331.65「我去打药」。前两句是队友闲聊/意图宣告，**零报点、零呼救、零交火喊话**。按 §5「自动标签不能单独当『这里有战斗』的证据」，转写**不足以**把这段从跑图翻成对峙；同时按 §5.1，否定跑图需要「高清帧 + 连续战斗语音」双重确认——本轮**高清帧这一半已足**（4K 逐帧 15.27 s 零三信号），语音这一半是**空档而非反证**，不构成矛盾。

**为什么分界点是 320.267 而不是 318.3 或 312.0**：
- `S 318.3` 落在「落印粉末」传送演出的中段（`S 318.0` 是近乎全黑的暗域紫雾帧）。以它为界，等于把 1.97 s 的黑/紫传送画面留在片子开头，且**切在 VFX 中间**——不是任何可读的信号点。
- `S 312.0` 之后虽然出现红色 ping（有了目的），但**仍然看不见任何目标**。按标尺，「看得见目标敌人的接近/对峙」才属「留：拉扯、重新接战」的前奏；「朝一个 ping 跑」仍是跑图。
- `S 320.267` 是**目标第一次真正出现在画面上**的那一帧（首个世界锚定血/护甲条对 + 队友好名条），也是**最保守**的可辩护切口：再晚一帧就要开始切掉可见目标，再早一帧就是留位移。

**分界帧的精确性**：`n = 19216` 是 60 fps 实测的第一个出条帧（`w=255, h=16, f=0.89, rgb=(222,116,124)`）；`n = 19215` 及之前无条。60 fps 逐帧记录落盘于 `shots\adjudicate_v3_a\first_bar60.txt`。

### 问题 3：推头之后 `engage_start` 怎么改？

**约束**：`validate_combat_timeline.py`（`skills\naraka-highlight-studio\scripts\`，实读第 113 行）判据是

```
valid_range = 0 <= start < engage <= outcome <= end
```

`start < engage` 是**严格小于**。因此**不能**把 `engage_start` 也设成 320.27——那会直接 FAIL（这与 v3 给 combat_004 / combat_009 / combat_010 用 416.99 / 910.99 / 948.99 避让是同一类问题）。

**裁决：`engage_start = 333.0`**（`n = 19980`，新 P = 93.23）。

依据（按「首次出现伤害数字/受击反馈」的要求来选）：

1. **`S 331.0` 帧上是拾取卡「武鱼甲」**——玩家在舔包，**这一秒确定没有开打**，所以 engage 不可能早于 331。
2. **`S 333.0` 帧上是充满画面的巨大橙色火球** + 横幅「暗域将在 10 秒后开启」——这是本场**第一处可见的敌方打击/命中反馈**，是 4K 逐帧能钉死的最早一帧。
3. `S 334.0` 起 seg4 记「红血条 + 锁定线」、`S 336.0` 记「正面对空、敌人红血条清晰」，与 333.0 连续，不存在断窗。

**为什么不取转写里的 331.65「我去打药」**：该句是 faster-whisper 的**合并段**（`331.65–334.36`），实际发声点不可定位；且它落在 331.0 的舔包帧附近，若当作受伤锚点就会与「331 在舔包」的画面直接冲突。按 §5「转写只是候选信号」，**不足以把 engage 提前到 331.65**。这一点如实登记为残余不确定（不构成 `needs_review`，因为 333.0 的画面证据独立成立）。

**`lead_in` = 333.0 − 320.27 = 12.73 s**（§5.2 默认 5 s；`lead_in` 无校验项，画面证据优先）。

**`start < engage` 复核**：`320.27 < 333.0` ✔ 严格成立。**`engage ≤ outcome ≤ end` 复核**：`333.0 ≤ 338.0 ≤ 345.0` ✔ 仍成立，`outcome_time = 338.0` 与 `source_end = 345.0` **均不需改动**。
