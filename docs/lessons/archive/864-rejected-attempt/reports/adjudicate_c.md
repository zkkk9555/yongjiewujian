## 0. 两个必须先说清楚的方法论结论（否则后面的秒点会被误读）

### 0.1 这块面板是**常驻可开关**的背包面板，不是偶发的"5 秒事件"

面板形态固定为「任务 / 背包 / 地图」标签 + `强化背包` + `魂玉背包` + `道具背包` + `武器背包` + `法门属性加成` + `拾取预设：开`。它**半透明**，会多次开关，**每次的货币与物品数都不同**。

| 出现区间（源秒） | 面板上的货币 | 归属 |
|---|---|---|
| 229.0–234.0 | 5450 | combat_001 段中 |
| 252.8–254.1 / 255.9–256.7 / 257.6–259.4 / 260.9–261.8 | 6350 / 6800 / 6800 / 6800 | combat_001 尾窗 |
| 265.7–266.4 | 7250 | combat_001 尾窗（**切点正落在此块内**） |
| 284.0–285.x / 299.5–300.6 / 302.x–303.x | 8600→9050 / 9800 / 9800 | 删除段 `[266,305)` 内 |
| 405.2–416.6（两次闪断共约 1.8 s） | **16250** | 删除段 `[404,412)` + combat_004 前置 |

**这直接推翻了我的第一版自动检测**：以某一帧为模板做整屏匹配，会被货币/物品漂移打败（`panel.py` 在 253 判 28%、在 265.5 判 16%，全都判错）。**因此本报告的每一个"面板开/关"结论，都以人工逐帧目视的 1920×1080 裁切表为准，数值指标只用于把边界收敛到 0.1 s 的候选区间。**

### 0.2 `make_route_frames.ps1` 烧进画面的时钟在 fps≠1 时是错的

脚本烧的是 `SegStart + n*$Fps`（例如 SegStart=415、fps=2 时第 2 格烧 `+4164`），而**文件名**才是对的（`SegStart + i/fps`）。本报告一律按**文件名**取证；引用烧录时钟时只作参考。
