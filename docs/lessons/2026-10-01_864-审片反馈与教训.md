## 2. 由此确立的规则（建议直接写入工作流文件）

### R1 · 面板不自动等于「待清除 UI」

**旧口径的问题**：现行判定标尺写的是「删：……全屏 UI（除属收束环节的）」。这条**只把「收束环节」当豁免**，于是战斗中的一切面板都被默认为该删——这正是本次连续四版出错的根源。

**新口径**：

> 判断一个面板该不该删，**不看它是不是面板，看它在不在这场战斗的因果链里**。
>
> - 打架中途**舔包、换武器、补物资、拿魂玉、选法门**＝**战术动作，是战斗内容本身** → **一律保留**
> - 只有当面板出现时，**这场战斗的结果已经明确且不属于任何收束环节**（例如打到一半玩家停下来整理仓库） → 才允许挖除
> - 判断依据是**画面内容与语音**，不是 UI 元素的类型

**反例（本任务实证）**：`combat_003` 在源 406–412 开着「选择强化」三卡 + 四栏装备面板，语音同期是「我还没选法门呢」。这块面板被 v1–v4 当成待清除 UI 挖掉，结果把一场完整战斗从中间切开——而它其实是用户所说的**「打药／补给」步骤**。

### R2 · 「一场完整战斗」的边界定义

> 一场完整战斗 ＝ **对同一队（或那两三队）敌人的第一次接战，到最后一次交战结束**，**中间的每一次战术停顿都属于这场战斗**：
> 拉开距离、脱离战场、打药／补血、舔包、换武器、拿魂玉、选法门、重新进场——**一个都不许切**。
>
> 只有当**换了对手**、或**发生了真正的场景／时间断裂**（去城镇交易、结算界面）时，才算下一场。

**这条规则的两个推论**：

1. **不许有「战斗中挖洞」** —— 在 `(engage_start, outcome_time)` 区间内**不允许任何 `excluded_inside`**
2. **不许有「战斗中切边界」** —— 相邻两场战斗若战斗流程延续，**必须合并成一段连续画面**，间隙（哪怕只有 6 秒）也要包含进去

> ⚠ **关键教训**：`excluded_inside`（洞）和 `episode` 边界**是同一个问题的两种形态**。清掉所有洞**不等于**战斗不再被切断——**边界本身也在切**。v5 修完了前者，被用户指出还漏了后者。

### R3 · 合并还是分开：判据是「战斗是否延续」，不是「间隔多少秒」

不要用「间隙 ≤ N 秒就并入」这种纯计时判据（现行标尺里的 `rejoin_window 12 s` 容易诱导出这种做法）。**正确做法是逐帧核实间隙内容**：

| 间隙内容 | 处置 |
|---|---|
| 拉开 / 打药 / 舔包 / 换装 / 跑动 / 重新进场 | **合并**（同一场） |
| 换了对头、跑图、闲聊 | 分开 |
| 去城镇交易、结算、复活 | 分开（属战场之间的补给，不属于任何一场） |

**实证对比**（同一素材内）：

- 12.99 秒的间隙 = 拉开 + 强化面板 + 跑动 + 重新接战 → **合并**
- 0 秒的间隙 = 两场首尾本就相接于同一秒，源上完全连续 → **合并**（否则就是一道纯多余切口，视觉上会闪）
- 84 秒的间隙 = 「去买点东西去」「等下补充一下物资」→ **不合并**（并进去会把 84 秒商城塞进战斗里）

## 4. 流程性根因：为什么四轮审片全部漏掉

这是本次最重要的一条教训，**与个人能力无关，是任务拆解的结构性缺陷**。

### 4.1 没有任何一个角色的任务是「查被删掉的区间」

本任务共派出 **7 路对抗审 + 4 遍自审 + 3 路独立验收**，全部的任务书都指向：

- 「报告你这一区间的问题」
- 「只报 v{N} 自身的问题」
- 「逐条核销上一版的 N 条问题」
- 「核验本版冻结件」

**没有一份任务书要求过「检查被删除的区间里是否有被冤杀的战斗」。** 删除段的 `reason` 字段写得非常详尽（交易、导航、搜刮、补给，每条都有 18 条取证路径），看起来完全合理——但**没有任何人用独立的战斗信号去交叉验证它**。

### 4.2 派工时的「零新增」心理导致对已登记例外的默认信任

`combat_002` 的「前置跑图」从 v1 起就被登记为例外，v2/v3 每轮都只是**核对「实测范围 ≤ 授权范围」**。当实测 15.27 秒远超授权的 5.0 秒时，流程选择的是「修正秒点」而非「认定例外已被事实推翻、必须推翻例外」。**例外一旦登记就获得了不应有的免检地位。**

### 4.3 缺少一个明确的「删了可惜」复核角色

建议新增一类**独立角色**（不与对抗审/自审/验收合并）：

> **删除段审计员**：逐条 `deleted_intervals`，用**与画面判定无关的独立信号**（语音战斗词、音频活动、队友播报、击杀播报）交叉验证「这段真的没有战斗」。
> 任一命中 → 强制人工复核，并回看该间隙前后是否属于同一场战斗。

本任务中，指挥正是用**对 11 条删除段做语音战斗词扫描**才逮到 E1 的。

### 4.4 判定标尺的措辞把执行者引向了错误方向

现行标尺的「删：……全屏 UI（除属收束环节的）」隐含了「面板默认该删、收束是例外」；而正确的关系应该是「**战术面板默认该留，只有非战斗状态的整理才是例外**」。**一条措辞的偏差，会被 7 个审片员一致地执行成 4 个版本。**

## 5. 本次证明有效、应当固化的方法

| 方法 | 说明 |
|---|---|
| **删除段语音战斗词扫描** | 对全部 `deleted_intervals` 做转写战斗词匹配（杀了/开大/他要走死/拉药/弹太快了…），命中即回看 4K 帧。零图片成本，是逮到 E1 的唯一手段 |
| **间隙逐帧定性后再决定合并** | 不看秒数，看间隙里画面到底在干什么（跑图 / 补给 / 换对手）。本任务据此正确合并 4 对、正确保持分开 5 对 |
| **形容词人「被授权上限」** | 已登记例外 = **授权额度**，不是免检牌。实测超出授权即须推翻例外 |
| **数值锁死复核** | 只改 JSON 散文层（`boundary_reason`/`notes`/`evidence`）后，重算切口与已渲染映射做**逐字段比对**，确认零差异才敢断言「无需重渲」 |
| **裁决独立于执行者** | 两次定点裁决分别推翻了执行者（指挥）与审片员（adv6）的结论，且都给出了帧级证据。**当执行者与审片员冲突时，需要的是第三方裁决，不是谁更自信** |
| **可疑自动化结论必须上 4K 目视复核** | 本任务中程序化红色检测被落日色调骗过（见 §7.1） |

## 6. 建议新增的门禁检查项

这些都可以做成程序化检查，成本极低：

| 编号 | 检查 | 判据 | 拦截的错误类型 |
|---|---|---|---|
| G-1 | **战斗中零挖洞** | 对每场，统计 `excluded_inside` 中满足 `start ≥ engage_start 且 end ≤ outcome_time` 的条数，必须 **= 0** | E3 类 / 面板被挖 |
| G-2 | **零间隙假切口** | 相邻两场的 `source_end` 与下一场 `source_start` 不得相等（相等说明被硬切了一刀却没删任何东西） | 无内容却闪一下 |
| G-3 | **删除段战斗词审计** | 每条 `deleted_intervals` 内不得出现战斗类语音；命中即 FAIL 并要求人工复核 | **E1 漏战** |
| G-4 | **场首不是动作中途** | 每场第 0 帧不得处于技能／滑翔／位移的过程帧（需人工或帧级证据确认一次，登记进时间线） | E3 类 |
| G-5 | **场尾不是流程中途** | `outcome_time` 到 `source_end` 之间的内容，不得是「拉开 → 补给 → 再进场」这种**尚未走完的流程**；若是，须与下一场合并 | **E2 类** |
| G-6 | **相邻续战检查** | 相邻两场间隙内若出现战斗语音或敌方名条，则必须已合并 | E2 类 |
| G-7 | **例外授权额度** | 每个已登记例外必须带一个**量化授权上限**；实测超出即 FAIL | §4.2 |

## 7. 本次指挥自身的技术性错误（供排查工具链时参考）

这些与剪辑判断无关，但都真实发生过：

| # | 错误 | 后果 | 教训 |
|---|---|---|---|
| T1 | 用**程序化红色像素检测**判断「有无敌方血条」，命中即质疑审片员 | **判断错了**。4K 逐像素复核证明那些红段是**落日粉紫天空 BGR(174,177,228)**、紫/品红护甲条、妖刀进度条、播报栏 | 本类画面的落日色调 + 品红 HUD 会骗过阈值检测。**凡判「有敌方红条」必须上 4K 目视复核** |
| T2 | 采信 `shots\segN\hd\tXXXX.0.jpg` 的**文件名秒点** | 实测存在**系统性 +0.4667 s（+28 帧）偏移**（两帧独立复核，偏移完全一致） | 该套帧**不能**作为秒点真值；须用直接 `-ss` 抽帧或帧号法 |
| T3 | 跑 `blackdetect` 时误用 **`-af`**（音频路径） | 它是**视频滤镜**，filtergraph 直接报错退出 → 日志里「零命中」是假的，把一个假结论写进了冻结件表 | 视频滤镜用 `-vf`、音频滤镜用 `-af`；生成日志后必须逐段确认非空 |
| T4 | 把「该挖 UI」当成**硬指标**，没算挖洞的观感代价 | 连续四版把 11 场战斗挖成 30 段 | 任何剪除动作都要同时评估「它造成的接缝代价」 |
| T5 | 用户说「**类似的问题肯定还有**」时，仍按点修 | 第 5 版只修了用户点名的 1 处，第 6 版才发现同类共 4 处 | 用户说"抽查"就是**要求系统性排查**，不是许可只修他说的那处 |

## 8. 术语表（永劫无间，用户在反馈中使用的说法）

| 说法 | 含义 | 在剪辑判断中的意义 |
|---|---|---|
| **开大** | 释放大招 | 若入片时已经在开大状态 → **前置战斗很可能被删了**，应立即回查该场的 `source_start` 之前 |
| **舔包** | 打开地上的背包／击杀掉落 | 战斗中舔包＝**战术动作，属战斗内容，不该挖** |
| **打药** | 使用药剂／补给 | 同上；用户口中「打药」涵盖整个补给流程（打开面板→选择→关闭） |
| **拉出战场 / 再进场** | 脱离交战 → 补给 → 返回交战 | **这是同一场战斗的一个环节**，切在中间即为截断 |
| **法门** | 技能／流派选择（对应「选择强化」面板） | 同上 |
| **魂玉** | 该游戏的装备养成系统 | 面板中反复出现，属常规操作 |
| **败北** | 失败结算画面 | ⚠ 与「失败」不是同一个词；曾因写成「失败」被要求更正 |
