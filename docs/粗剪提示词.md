# 粗剪提示词（通用唯一版）

> 用途：开一个新对话，复制下面 `=== 复制线内 ===` 整段，**只改「素材：」那一行的绝对路径**，然后发送。
>
> **新剪和续剪用同一份**，不需要两套模板：素材已经在 `123\` 下有同编号目录时，它会自动走续剪分支。
>
> 本文件取代早期的 `PROMPT_TEMPLATES_GOAL.md` 与 `PROMPT_TEMPLATES_OPENCODE.md`。
> 那两份已从 `docs\` 移除：前者依赖 DeepSeek 专属的 `create_goal`、后者绑定 opencode，
> 都不通用；两者还都指示「解析 WinGet 符号链接 Target」——那份 WinGet FFmpeg 已卸载，照做必撞墙。

## 设计原则（改这份文件前先看）

1. **薄。** 只写「不能猜」的部分：剪辑定义、路径纪律、看图上限、交付格式、续剪分支。
   执行细节一律交给 `skills\naraka-highlight-studio\`，**不复述**——复述会产生第二份副本，
   两份不一致就是漂移的根源（旧提示词就是这么烂掉的）。
2. **通用。** 不出现任何 harness 专属接口（`create_goal`、`subagent` 等）。
   换客户端、换工具链都不用改。
3. **项目工具路径不硬编码。** ffmpeg / python 这类会被重装或挪位的工具，位置一律以预检脚本输出为准，
   提示词里不写它们的 exe 路径。**唯一例外是 Git Bash**（`C:\Program Files\Git\bin\bash.exe`）——
   它是系统安装的稳定路径，写出来是为了让 `.sh` 脚本能被正确调用；这不是漂移源，别当冗余删掉。
4. **唯一允许的重复是看图上限。** 因为违反它不是报错，是整个会话报废，代价太大，值得付这点重复成本。

═══ 剪辑定义（唯一标准）═══

一场战斗 = 从第一次明确交战开始，到结果明确（击杀／团灭／敌人逃脱／
玩家脱险／胜负已分）为止，外加短暂收束。

- 战斗中不切走。宁可留长，不漏战、不切断。
- 删除：跑图、搜物资、等待、重复操作、长时间无事件。
- 保留：拉扯、救援、追击、躲技能、重新接战——这些是同一场战斗的一部分。
- 边界不确定的，保留并标记，不要自己截断。
- 自动标签只是候选信号，不能单独当作"这里有战斗"的证据。

═══ 任务目录（新剪和续剪共用这一段）═══

统一落在 C:\Project\永劫无间\123\<编号>.<素材名去扩展名>。

先判断是哪种情况：
- 123\ 下已有同名的 <编号>.<素材名> 目录 → 续剪
- 没有 → 取 123\ 下现有任务目录的最大编号 + 1，新建；
  123\ 为空则从 1 开始。不要凭记忆写死编号，跑这条命令取：
  $nums = Get-ChildItem 'C:\Project\永劫无间\123' -Directory | ForEach-Object { if ($_.Name -match '^(\d+)\.') { [int]$Matches[1] } } | Where-Object { $_ -ne $null }
  ($nums | Measure-Object -Maximum).Maximum + 1

【如果是续剪】
1) 动手前先盘点，用产物判定进度，不要凭目录里有哪些文件：
   - 时间线：拿 combat_episodes_vN.json 跑一遍校验，没通过就不算到那一步
   - 预览：拿 ffprobe 确认存在且能完整解码；解不开就当作没有，重渲
   - 门禁：找出最后一个通过的冻结门禁文件，它的版本号就是当前的 N
2) 版本号接着往后排（vN+1、vN+2……），绝对不要从 v1 重来，
   更不要覆盖已有的文件——旧版本是审计依据，覆写等于把之前的记录抹掉。
3) 已经通过门禁的步骤不要重做；没通过或做到一半的接着做完。
4) 目录存在但是空的（上次刚建就没开工）→ 直接在里面从头做，不要另起目录。
5) 上次要是卡在环境问题上，先重跑预检；问题解决了就正常往下走，
   不要因为"上次失败过"就跳过该做的分析。

═══ 不可违反 ═══

- 源盘 E:\OBS 和 E:\PR导出 只读，永不写入、覆盖、改名。
- 看图是硬红线：单次请求累计不超过 50 张（含历史已看），单轮新增不超过 10 张。
  看之前先数，再跑 C:\Project\永劫无间\scripts\check_image_budget.ps1 打印分轮计划。
  超过 10 帧先拼联系表（一张联系表算 1 张）。宁可多看一轮，不可多看一张。

═══ 交付标准 ═══

- 交付的是这一轮你能做到的最好版本。发现能确定的改进——某场战斗收早了、
  该留的收尾被切掉了、某段明显该并进上一场——先改完、重新校验，再交付。
  不要把自己能修的问题写成"待办"丢给我。
- 但也不无限打磨。skill 的门禁通过就算完成，达标就停。

  说过了就一路做完（含验收与收尾清理），不要再回来问我；没说就不许自己出。

═══ 环境降级 ═══
