# 高质量批量成片工作流

## 目标

用户只需要提供素材路径并对成片反馈。Agent 负责素材整理、当前任务的 BGM 选择、战斗事件分析、节奏编排、音效与特效、质量检查和最终导出。中间分析文件保存在编号任务目录内，默认不要求用户参与开发过程。

专属 skill 原型：

```text
C:\Project\永劫无间\skills\naraka-highlight-studio\SKILL.md
```

## 批量输入

每天的七八把对局作为一个批次处理，而不是每把单独生成一个成片：

```text
素材文件夹
  → 批次清单与去重
  → 每把对局独立探测/分析
  → 全批次事件评分
  → 选出一条完整节目结构
  → 生成预览和最终成片
```

每把对局仍然保留独立的候选片段和事件包，方便后续替换某一秒的画面，不重复分析其他素材。

## BGM（当前暂缓）

当前项目暂不接入抖音开放平台的动态 BGM 榜单接口，也不自动抓取或下载平台音频。没有本地/用户提供的 BGM 时，直接使用原始游戏声、语音和事件音效完成成片，避免生成“本地无 BGM、上传后再手动补音乐”的割裂交付。

如果用户提供本地音频，流程仍然可以分析 BPM、节拍、起音和能量段，再把战斗事件、慢放、停顿、闪白、文字和冲击音效对齐到实际音乐并直接烧录进最终成片。

本地素材库结构：

```text
C:\Project\永劫无间\assets
├─ bgm
├─ sfx
├─ overlays
└─ fonts
```

每首音乐需要记录来源、日期、BPM、情绪、段落和使用方式；每个音效和字体也记录来源信息。

## 事件驱动剪辑

不让模型直接凭音量决定剪点，而是组合画面变化、HUD/击杀反馈、音频峰值、语音关键词和上下文，形成事件包：

```text
进入交战
  → 振刀/连招/拆火/大招
  → 反打或击杀结果
  → 战斗收束
```

主要事件类型：

```text
振刀、反打、连招、残血极限、帮队友拆火、大招、单杀、连续击杀、脱险
```

每个事件保存源时间、节目时间、冲击点、前置时长、结果、置信度和保留理由。战斗没有收束前，不为了追求短时长切到下一场。

## 默认风格

当前第一版风格为“高燃卡点”：

- 横版 4K60；
- 目标成片约 45–90 秒，可按素材强度调整；
- 纯游戏集锦默认关闭语音字幕；
- 只在振刀、击杀、大招、残血和拆火等节点使用少量文字；
- 慢放、停顿、闪白、缩放、轻微震动和冲击音效以可读性为先；
- BGM 在语音和关键游戏声音处自动降低；
- 不把每个剪点都强行对齐到每个鼓点。

风格配置位于：

```text
C:\Project\永劫无间\style_profiles\high_energy_v1.json
```

以后可以增加电影感、队友拆火、教学解说、搞笑语音等风格，但共享的分析和质量门禁保持一致。

## 最终交付和内部重建能力

用户默认收到：

```text
master_*.mp4
review.mp4
```

项目内部同时保留：

```text
source_probe.json
batch_manifest.json
event_candidates.json
beatmap.json
markers.csv
音频 stems
字幕/关键字文字轨道
特效配方
可重建时间线
```

这样用户只看最终结果，但后续如果反馈“只改一秒”，工作流可以只重建对应镜头和最终拼接，不必重新跑完整批次。

## 质量门禁

交付前必须检查：

- 原始素材未修改；
- 没有战斗未结束就跳切；
- 没有双层字幕；
- 没有音画漂移、削波、黑帧或意外冻结；
- BGM 没有盖住关键游戏声音或语音；
- 特效没有遮挡振刀、击杀或大招本体；
- 4K、60fps、编码器、VBR 和体积符合源素材与交付配置；
- 预览和最终文件都完成完整解码检查。

## 反馈进化

用户只需要评价成片，例如：

```text
振刀前多留一点过程；闪白少一点；BGM 在队友说话时再低一些；击杀文字保留但不要大招文字。
```

Agent 将其转换为结构化反馈，判断是一次性修改还是长期风格偏好，再更新版本化的 style profile。一次特殊要求不会直接污染所有未来任务。
