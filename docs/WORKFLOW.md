# 标准视频剪辑工作流

## 任务目录

每次收到素材路径后，先取素材文件名（去掉 `.mp4` 等扩展名），在
`C:\Project\永劫无间\123` 中分配下一个未使用编号，建立：

```text
C:\Project\永劫无间\123\<编号>.<素材文件名>
```

该目录是任务的唯一输出目录：初检结果、候选清单、字幕、源时间线、联系表、低清预览、修订版和最终成片全部放在这里。原始素材保持在 `E:\OBS` 或 `E:\PR导出`，不复制、不覆盖。

当任务包含多把对局、本地 BGM、卡点、特效或“只交付成片”要求时，转入项目内的生产级 skill：[skills/naraka-highlight-studio/SKILL.md](../skills/naraka-highlight-studio/SKILL.md)。本文件保留基础分析和渲染约束，生产级 skill 在其上增加批次清单、事件时间线、音乐节拍、效果配方、缓存和质量门禁。

如果目标是“把每一场战斗完整截出来的高质量粗剪”，使用该 skill 的
`complete_combat_roughcut` 模式，并读取
`skills/naraka-highlight-studio/references/complete-combat-roughcut.md`。
这个模式把完整战斗作为最小剪辑单位，战斗未出现明确结果前不得转场；
它与“只截精彩瞬间”的高燃成片模式不同。

## 总览

```text
源素材
  → 环境检查
  → FFprobe 元数据
  → 音频提取
  → faster-whisper 人声转写
  → PySceneDetect 场景边界
  → Auto-Editor 音频活动
  → FFmpeg 缩略图和候选片段
  → 候选评分
  → 源时间线
  → 低清粗剪预览
  → 用户确认
  → 源素材 4K 最终渲染
```

## 阶段 0：环境检查

先跑只读预检，**以其输出为唯一环境真源**：

```powershell
& 'C:\Project\永劫无间\scripts\check_video_environment.ps1'
```

退出码：`0` = 可开工，`2` = 存在 BLOCKER（看 `BLOCKERS:` 列表），`1` = 检查本身没跑完。需要机器可读结果加 `-Json`。

检查重点：

- **主 Python 是否真的能启动**（不是「文件在不在」）。预检用哨兵实执行判断，起不来即 BLOCKER。
- faster-whisper、PySceneDetect、Auto-Editor 是否可用（依赖上面那条）。
- CUDA/cuBLAS/cuDNN 目录是否存在。
- large-v3 模型缓存是否存在（权重在盘上 ≠ 能用）。
- FFmpeg/FFprobe **是否被解析出来**（成对存在才算），实际路径以预检输出为准，不要硬编码。
- LosslessCut 是否存在。

> 踩坑记录：旧版预检只做 `Test-Path`，把一个文件存在但起不来的解释器报成 `[PASS] canonical Python`，导致工作窗口以为环境可用、直接撞墙。**判据必须是「能不能跑」，不是「在不在」。**

检查失败时先记录缺口，不要直接创建新的任务虚拟环境或执行 pip 安装；只有确认共享环境缺少组件并得到明确安装要求时才处理环境。

### 当前实况（2026-09-29）

预检当前返回 **`ok=7 warn=0 blocker=0`，退出码 0**：Python 3.12.10 可运行，faster-whisper / PySceneDetect / Auto-Editor 全部可用，GPU 转写实跑通过，**字幕可做**。

此前（2026-09-29 之前）预检返回 `blocker=1`：venv 绑在一个已被系统清理的临时缓存解释器上，导致三个工具全部不可用、字幕做不了。根因与修法见 `AGENTS.md §2` 环境铁律第 2 条。**降级路径（纯视觉 + 音频活动信号、出无字幕版）仅在预检再次报 BLOCKER 时启用，且必须在任务目录写明缺口、不得声称满足完整门禁。**

## 阶段 1：探测源素材

保存 `source_probe.json`，至少记录：

- 时长；
- 宽高；
- 帧率；
- 视频编码器、像素格式和平均码率；
- 音频采样率、声道和码率；
- 文件大小。

源文件超过 2 GB 时，分析可以分段，但原始素材仍保持只读。

## 阶段 2：音频和字幕

1. 从源视频提取 16 kHz 音频，必要时分别检查左右声道。
2. 用 faster-whisper GPU 做转写。
3. 使用 VAD、短分块、词级/短语级时间戳和置信度过滤，避免字幕跨越几十秒卡住。
4. 对《永劫无间》专有词、人名、武器名和常见口头语建立修正规则。同一文本在节目字幕内连续重复出现（835 v11：源转写"他队友是狐狸"复读15条）必须按复读刷屏过滤，只保留首条；真实短语不会连续重复，不受影响。
5. 生成源时间轴字幕，再根据粗剪时间线映射为预览字幕。映射时必须做跨段断裂检查（835 v11 沉淀）：凡源字幕横跨 episode 边界或落在删除间隙，必须按节目切点切断或丢弃，不得让一条字幕横跨剪辑切点（如 1125.1–1142.9 横跨 004 尾 1133 与 005 头 1140）。

字幕分析的目标是保留真实人声，但 faster-whisper 本身不做可靠的说话人身份识别。如果需要区分“我”和“队友”，优先使用 OBS 独立音轨，其次才考虑说话人分离模型。

## 阶段 3：画面和活动分析

- PySceneDetect：提供场景变化和镜头边界。
- Auto-Editor：提供音频活动、静音和低活动参考。
- FFmpeg：提取缩略图、关键帧和指定时间范围的画面。
- 关键词/音频峰值：辅助发现击杀、技能、求救、反打等时刻。

这些信号需要合并。场景边界、音量峰值或字幕关键词都只是候选证据，不应直接当成最终剪点。

### 看图限流（全模型硬性红线，每轮持久有效，违者会话作废）

无论使用什么模型（含 `muse-spark-1.3-contributor-free` 及任何后续模型），上游单次请求携带的图片总数上限都是 50 张，绝对不允许超过；超限会导致会话无法继续，只能换新窗口。计数口径是累计口径：上游按一次请求内携带的全部图片结算，包括历史轮次已看过的图加上本轮新增（`Read` 图片 + `get_app_state` 截图 + `screenshot` + `zoom` 裁图后再次判读）。

- 看图前必须先做预算：`thumb_*.jpg` 这类目录先 `ls`/`dir` 计数并写出数字，再运行 `scripts\check_image_budget.ps1 -ImageDir <缩略图目录> -AlreadySeen <历史已看数>` 打印分轮计划；总数 >50 或累计会超 50，必须拆成多轮；不做预算不准看图，同一轮不得为省事合并多批。
- 单轮新增预算：每轮新 `Read` 的图片不超过 10 张；常规每批只看 4–10 张；单轮内所有图片工具加总仍不得超过 50 张。
- 缩略图先抽稀（如 1/10fps、320px 宽），超过 10 帧优先用 `scripts\make_contact_sheet.ps1` 把联系表拼成一张再看（一张联系表只算 1 张），只对战斗边界前后小批量补帧。
- 每轮看完先写出核实结论，下一轮按累计口径调小预算后再继续；历史已看图太多时开新窗口继续。
- 失败教训：曾因一次性提交 53 张导致会话作废；`sess_03bfff9d` 因小批量多轮累加超 50 同样作废。宁可拆多一轮，不可多看一张。完整口径见根目录 `IMAGE_LIMIT.md` 与 `AGENTS.md §9`；如有冲突以 50 张上限为准。

## 阶段 4：候选评分与时间线

《永劫无间》候选片段应尽量保留完整事件链：

```text
进入交战
  → 关键动作（振刀/连招/拆火/反打）
  → 结果（击杀/脱险/队友存活）
  → 必要的收束
```

评分可以参考：战斗密度、音频峰值、字幕关键词、画面变化、击杀反馈和前后上下文。不要为了追求短时长，在战斗尚未结束时切到下一段。

时间线必须同时保存：

- 源开始时间；
- 源结束时间；
- 节目时间线开始/结束时间；
- 片段分类和保留理由。

完整战斗粗剪模式还必须保存：

- `engage_start`：第一次明确交战；
- `impact_points`：关键动作和转折点；
- `outcome_time`：击杀、脱险、逃脱或本轮战斗结果明确的时间；
- `needs_review`：边界不确定时保留候选，不自动切断；
- 被删除区间的类别和抽查结果。

## 阶段 5：低清预览

预览用途是审片，不是最终画质。一般使用 1280×720 或其他低清规格（全外挂字幕，禁烧录禁内嵌）：

- 无字幕版：用于检查切点、战斗完整性和画质布局；
- 外挂字幕版：用于检查字幕时间，字幕只以 SRT 外挂交付、播放器按需挂载。

不出烧录预览。预览确认前不输出大体积 4K master。

完整战斗粗剪模式的预览审片重点是：

1. 每一段是否从交战开始保留到结果明确；
2. 中间是否错误删除了拉扯、救援、追击或重新接战；
3. 是否仍然混入搜物资、跑图、等待或长时间无事件；
4. 两场战斗之间是否在上一场结果明确后再衔接。

## 阶段 6：用户审片反馈

反馈应优先标记：

- 哪个源时间点的战斗被切断；
- 哪个片段应该删除或延长；
- 哪条字幕不准或需要删掉；
- 是否只保留玩家/队友人声；
- 是否需要更高燃节奏、慢放、放大或音乐卡点。

修改应回到源时间线，不要在已经导出的预览 MP4 上二次剪辑（预览一律无烧录字，不存在可叠剪的烧录层）。

## 阶段 7：最终渲染

最终版必须从原始 MP4 按时间线重建。若源素材是 4K60 H.264 VBR，则默认保持：

- 3840×2160；
- 60fps；
- H.264 NVENC；
- 受控 VBR；
- 音频 48 kHz 双声道；
- `+faststart`。

码率先参考源素材的平均码率。例如源视频约 16 Mbps，7–8 分钟精选片段可以使用约 18 Mbps 目标、28 Mbps 峰值；150 Mbps CBR 会把同样时长的成片无意义地推到数 GB，不作为默认方案。

最终版与预览一律干净画面：禁烧录、禁内嵌字幕流，字幕只以外挂 SRT 单独交付。渲染脚本 `scripts\seg_render_master.sh` **没有烧录开关**（原 `BURN=1` 分支已按项目铁律删除，且不得再加回来）。最终成片旁不保留同名外挂 SRT 的旧烧录防重规则已失效——现在根本不出烧录版，同名 SRT 即外挂字幕本体，按命名节正常保留在 `captions\` 异目录。

## 阶段 8：成片验收与收尾清理

出片不是终点。4K 成片落盘后固定走两步：

**第一步，验收**（`scripts\verify_master.sh`）：

```bash
bash scripts/verify_master.sh <master_mp4> <expected_program_sec> <log_file>
```

`expected_program_sec` 取 `scripts\read_episode_bounds.ps1` 对该时间线输出的 `PROGRAM=` 值。
逐项检查：完整解码（`DECODE_EXIT=0`）、零内嵌字幕流、成片时长与时间线切分清单吻合（容差 2 秒）。
任一不通过即退出非 0，不算交付。

**第二步，收尾清理**（`scripts\cleanup_after_master.ps1`，**固定步骤，不额外问用户**）：

```powershell
& 'C:\Project\永劫无间\scripts\cleanup_after_master.ps1' -TaskDir 'C:\Project\永劫无间\123\<编号>.<素材名去扩展名>'
```

删 `preview\` `cache\` `shots\` `audio\`（全部可由源素材再生），保留任务目录本身与
`timeline\` `reports\` `analysis\` `deliverables\` `captions\`。849 实测回收 3.38 GB / 共 3.39 GB，
审计记录约 10 MB 全留。**不要整目录手删**——会连带删掉"为什么这么剪"的唯一依据，并导致编号复用。
完整规则见 `AGENTS.md §7.1` 与 `skills/naraka-highlight-studio/references/deliverables-and-qa.md` 的 Post-master cleanup。
