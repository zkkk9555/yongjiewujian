# 视频任务统一输出目录

`C:\Project\永劫无间\123` 是本项目所有视频任务的固定结果根目录。

## 命名规则

每次开始一个新素材任务时，取素材文件名并去掉扩展名，在前面加上编号：

```text
123\<编号>.<素材文件名>
```

例如：

```text
123\1.830永劫无间 2026-06-27 21-52-17
123\2.下一个素材文件名
```

### 编号怎么取（2026-10-22 升级：撞号根治）

**建任务目录一律走分配器，不要自己算编号：**

```powershell
& 'C:\Project\永劫无间\scripts\new_task_dir.ps1' -Material '889永劫无间 2026-10-15 22-11-13'
```

它做五件事：

1. **加锁**（`123\.seq.lock` 独占句柄）——两个对话挨着开，也拿不到同一个号；
2. **幂等**——同一素材已经有目录就返回 `REUSE: <那个目录>`，**不再新建**
   （第二个对话接着剪同一个素材就行，这是「幸运花挨太近」那次的正解）；
3. **单调**——新号 = 现有最大编号 + 1；占用就顺延，绝不复用；
4. **留索引**——写一行进 `123\index.tsv`（编号⇥素材⇥创建时间⇥备注）；
5. **查素材顺序**——新素材号比当前最大的还小，就打印 WARN
   （你的规则：**数字越大的素材往后排**）。

输出只有两种：`CREATED: <路径>` 或 `REUSE: <路径>`。

**为什么不能自己算**（2026-10-22 事故）：老规则是「看最大编号 + 1」，
那是一个**读**操作，不是**分配**操作——两个对话挨着开，各自读到同一个 max，
就各自建了同一个号（实测：`34.888` 与 `34.889` 同时用了 34，
用户原话：「两个对话都以为自己是 34」）。而当时那道体检门**只把撞号判成 NOTE**，
挂了一周没人管。现在三件事一起改：取号加锁、撞号是硬违规、目录不在索引里就是违规。

**体检命令**（看现状，不建目录）：

```powershell
& 'C:\Project\永劫无间\scripts\check_task_numbering.ps1'
```

它会报：编号是否唯一、命名有没有被截断、有没有空壳目录、索引齐不齐、素材号顺序对不对。
退出码 0 = 干净；**撞号现在退出码是 1**。

不要在任何文档里写死「下一个编号是 N」——那种数字只是某一天的盘上快照，交付完目录被删就过期了。
真实映射看 `123\index.tsv`。

### 建目录时不要拼字符串（2026-10-01 事故）

**目录名必须等于「源文件名去扩展名」，原样照抄，一个字符都不改。**

曾经的写法：把素材名按空格切分再取首尾拼接（`($parts[0]) + ' ' + ($parts[-1])`），
本意是「去掉中间的日期」，实际把日期吞了：

```
863永劫无间 2026-09-30 02-57-13   素材真名（三段）
        ↓ 按空格切分取 [0] 和 [-1]
863永劫无间 02-57-13              错名：少了 2026-09-30
```

这个错特别难发现：**不报错**（路径合法）、**不留文件**（只有空目录）、
**git 看不见**（git 不跟踪空目录）。结果它白占了编号 20。

**正确写法**——交给分配器，它内部就是「去扩展名、原样照抄、不加工」：

```powershell
& 'C:\Project\永劫无间\scripts\new_task_dir.ps1' -Material 'E:\PR导出\863永劫无间 2026-09-30 02-57-13.mp4'
```

（分配器接受带路径、带扩展名的素材名，会自己去扩展名、只取文件名。）

`check_task_numbering.ps1` 会把这类目录判成 `STEM_TRUNCATED`，预检也会报 WARN。
预检的野目录检查只看**项目上一级**，看不到 `123\` 内部，所以这道编号门禁是必需的。

同一个素材任务的后续修订**沿用同一个编号目录**，不重新取号——分配器认得它，直接 `REUSE`。

## 目录内容

对应项目目录中统一保存：

- 源素材探测结果和分析报告；
- faster-whisper 字幕、转写统计和字幕修订版；
- PySceneDetect、Auto-Editor、FFmpeg 的分析结果；
- 候选片段清单、联系表和源时间线；
- 无字幕预览、外挂字幕预览（禁烧录禁内嵌，字幕只以外挂 SRT 交付）；
- 用户确认后的最终成片、编码参数和质量检查记录；
- 该任务后续生成的全部中间文件和版本文件。

原始素材仍然只读存放在 `E:\OBS` 或 `E:\PR导出`，不复制到项目目录、不覆盖、不改名。

### 出片后别删目录

4K 成片交付后，任务目录**留在原地**，由 `scripts\cleanup_after_master.ps1` 自动删掉里面可再生的重量
（`preview\` `cache\` `shots\` `audio\`），保留 `timeline\` `reports\` `analysis\` `deliverables\` `captions\`。

**但「保留」指的是留下证据，不是留下重量。** 保留目录里**不该留任何音视频文件**——
它们可再生（源片在 E 盘完好，auto-editor / FFmpeg 重跑一次就有），而它们携带的结论
都在同名 JSON / CSV / 报告里。收尾清理脚本会逐个删掉它们（2026-10-22 新增；
起因是 888 的 `analysis\autoeditor_ref.mp4`——344 MB 的 4K 静音参考片——
在任务结束后还占着 328.6 MiB，用户问「为什么还有三百多兆」）。
卫生门也会拦：保留区里出现 >10 MB 的音视频 = 硬违规。

849 实测整个目录 3.39 GB，其中 3.38 GB 是那四样可再生重量，真正值钱的是约 10 MB 的时间线与审计记录
——那是"这段为什么留、那段为什么删、谁核过"的唯一依据。**删重量、留证据、留目录壳。**

整目录手删有两个后果：一是把依据一起删掉，二是目录没了会导致编号复用（见「编号怎么取」）。
历史任务 848 / 852 / 853 的目录已由用户手删，依据已不在——新的任务请按上面的自动清理走。

### 收尾前：经验必须落盘（2026-10-01 起）

任务目录要留的不只是时间线和审计，还有**这一局的经验**：
`reports\workflow_notes_<任务目录号>.md`（文件名用**任务目录号**，不是素材号）。

覆盖情况（实测 2026-10-01）：10 个任务目录里只有 5 份。缺的那几个意味着
「这一局学到了什么」随目录一起消失了——`123\README.md` 里的编号规则、审核手册里的判据
都拿不到它们。

用户说「**去收纳经验**」时，跑 `scripts\collect_lessons.ps1`：

```powershell
& 'C:\Project\永劫无间\scripts\collect_lessons.ps1'
```

它扫所有任务目录的 `workflow_notes_*.md` 和 `docs\lessons\`，对照 `docs\lessons\POOL.md`
列出**还没吸收**的条目，并报覆盖率与命名合规。**没写「吸收去向」的不算吸收。**

> **注意**：如果任务目录要被**整目录手删**（不是走 `cleanup_after_master.ps1`），
> 里面的 `workflow_notes` 和专题复盘会一起没。删之前先把要留的复制到 `docs\lessons\`
> ——864 就是这么抢救的（原件现在在 `docs\lessons\2026-10-01_864-审片反馈与教训.md`）。
> 复制之后确认工作流文件里没有残留指向被删目录的路径引用。
